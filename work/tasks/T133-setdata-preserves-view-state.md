# T133 — `setData` скидає стан перегляду: згортання, виділення, підсвітку й фокус пошуку

**Пріоритет:** P2 (не регресія, див. нижче) · **Статус:** 🔵 не почато · **потребує `spec-flow`**
(змінюється задокументована семантика публічного `setData`)
**Джерело:** діаграма взаємодії dg ↔ хост, знахідка D1
(`work/reports/library-boundary-audit/host-interaction-diagram.md` §2), 2026-11-05.
**Власник відповідальності:** бібліотека (рішення власника «я — бібліотека»; хост — знімкова модель).

## Факт (з коду, на стенді не перевірено)

SDK `setData` (`packages/sdk/src/OrgHierarchyDiagram.ts:1364-1390`):
- `this.data = next` — прапорці `position.expanded`, які SDK записав при згортанні, губляться, якщо хост їх
  не передав назад;
- `seedExpandedPositionsFromData()` — рольовий дефолт: у поточній org усе з `expanded !== false` розкрито;
- `applySelection(null)`, `viewState.highlightedNode = null`, `viewState.foundFocus = null`.

Хост `cassiopeia-admin-ui`:
- мапер `position-tree-to-dg-diagram.ts` `expanded`/`collapsed` не пише;
- контролер `use-positions-diagram.ts:405-422` шле `setData` на кожну зміну `data`, `draftTree`, `draftRoots`,
  тобто й на кожен жест у чернетці (стек жестів, host ADR-0067), а виділення відновлює лише в обробнику кліку
  (`:250-258`).

**Наслідок для користувача (очікуваний, не виміряний):** після будь-якої правки чи рефетчу згорнуті гілки
знову розкриваються, а виділення, підсвітка шляху й фокус пошуку зникають. Камера лишається
(`preserveViewport`).

## Не регресія

Попередній GoJS-рушій хоста теж скидав розгорнутість на кожному `setData`
(`src/shared/lib/gojs-diagram/gojs-tree-diagram.engine.ts`, `setData` → `this.expandedKeys.clear()` + нова модель).
dg відтворює стару поведінку; ця таска — покращення UX, а не відновлення.

## Межа

- **Бібліотека:** переносити стан перегляду через `setData` на ті самі id: розгорнутість посад, виділення,
  підсвітку шляху, фокус пошуку. Вузли, яких більше нема, — випадають зі стану.
- **Хост:** нічого не додає (не мусить сіяти `expanded` і повторювати виділення).

## Відкриті питання для spec-flow

1. **Дефолт чи опція?** Зберігати стан завжди (змінює задокументовану семантику: `setData` «чистить виділення»)
   чи opt-in (`setData(data, { preserveViewState: true })` / прапорець конфігу)? Чинний контракт тримають
   тести SDK і демо — їх перелік знадобиться для рішення.
2. **Що з новими вузлами** у вже розгорнутому/згорнутому піддереві: успадковують дефолт ролі чи стан батька?
3. **Явний `expanded` у даних хоста** проти збереженого стану SDK — що перемагає?
4. **Виділення вузла, якого вже нема** — мовчки знімається чи летить `onSelectionChange`?
5. Чи стосується це й `staffExpandedOrgIds` / `organizations[].collapsed` (org-рівень), чи лише посад?
