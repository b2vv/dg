## Гап 1 — reparent не захищає кореневу посаду

Хост типізує кореневу посаду окремо (`HierarchyRoot`) і структурно вимикає для неї
move/merge/delete в меню — `build-position-menu-items.tsx:61-131`, три дії задизейблені саме
на корені.

`@org-hierarchy/sdk`: `checkReparent` (`packages/sdk/src/interaction/positionReparent.ts:44-60`)
відмовляє лише на чотири речі — `self`/`cycle`/`unchanged`/`unknown-id` — і **нічого не знає про
`isHead`**. `grep isHead` по `interaction/**` не дає жодного збігу поза одним використанням в
`OrgHierarchyDiagram.ts:1227` (пошук голови для `expandToDepth`, не guard). Тобто сьогодні нічого
не заважає перетягнути `isHead`-посаду під нового керівника — API це прийме.

## Гап 2 — move (cross-org) / merge / clone-structure відсутні

Хост має три дії, яких немає в SDK взагалі:

- **Move** — модалка переносу посади в **іншу** організацію (не reparent усередині тієї самої);
- **Merge** — злиття двох структур;
- **Клонувати структуру** — SaveBar secondary action, копіює **всю** структуру.

Усі три комітяться **одразу поза draft-чергою** й навмисно **не входять у undo**
(`use-positions-editing.ts:40`, задокументовано раніше в `questions.md` §D15). `reparentPosition`/
`movePersonToCell`/`shiftBlock` — усі три рівно про **одну** посаду в межах **наявної**
структури; жоден не рухає посаду між організаціями, не зливає дві структури й не копіює піддерево.

## Чому одна задача, а не дві

Обидва гапи — про те саме питання «що дозволено робити з посадою в edit-режимі», обидва виявлені
в тому самому проході, обидва зачіпають той самий контракт (`reparentPosition` + майбутні нові
мутатори). Розділяти на реалізацію все одно доведеться (root-guard — маленька, cross-org дії —
велика фіча), але задача одна, щоб рішення по одній частині не приймалось без огляду на другу
(наприклад: **move під новий батько в іншій org** — це вже майже те саме, що «Move»-дія хоста,
тож дизайн API для Гапу 2 варто звіряти з тим, чи не закриває він заразом Гап 1).

організації. Це і є реальний сценарій хоста («Move» в іншу структуру), тобто пастка вказує на
Гап 2. Тести переписані на ціль `out`; перевірено трьома мутаціями: гвардія знята → 4+2 червоних,
гвардія на `managerId` (та сама «зашилася надто широко») → 5 червоних, мовчазний catch повернуто
→ 2 червоні.
