## 2. P0 — архітектура та коректність

### D1 🔴 Будь-яка зміна перебудовує ВСЮ сцену

`DiagramRenderer.render()` (`:265-298`) починається з `this.layers.clear()` і далі створює
кожен view заново (`OrganizationNodeView.create`, `PersonNodeView`, контури, ребра).

Викликів `this.render()` в `index.ts` — **26**. Серед них:

| Дія | Рядок | Що перебудовується |
|---|---|---|
| **клік по вузлу / виділення** | `:1058-1078` (`select`, `selectMany`, `toggleSelection`, `clearSelection`) | уся сцена |
| **перетин порогу LOD (зум)** | `:439-449` | уся сцена |
| зміна теми | `:877` | уся сцена |
| expand / collapse | різні | уся сцена |

На заявленому масштабі (50k організацій) **клік мишею** перебудовує 50k view.
Виділення — стан підсвітки; воно не повинно торкатися дерева відображення.

**Що робити:** розділити `render` на `rebuild()` (дані/розкладка) і `repaint()` (виділення, LOD, тема).
Для `repaint` — пройтись по наявних `nodeViews` і оновити стилі. Мапи вже є — сьогодні
очищаються замість перевикористання.

→ **[T75](../tasks/T75-rebuild-vs-repaint.md)**

### D2 🔴 Немає захисту від паралельних `render()`

`render()` асинхронний: `layers.clear()` → далі `await` на текстури й контури. Захисту від
повторного входу немає; тригери перекриваються — зокрема колбек `onOrgClick` **усередині**
опцій рендера сам кличе `void this.render()` (`index.ts:~1180`).

Сценарій: клік під час рендера від LOD → другий `clear()` витирає те, що перший ще дописує →
дублікати / зниклі вузли; `nodeBoxes` / `nodeViews` розходяться з display-list.

**Що робити:** черга на один рендер (прапорець «йде» + «замовлено ще») або скасовуваний токен
після кожного `await`.

→ **T75** (робити **першим**)

### D3 🔴 View ніколи не знищуються — витік GPU-пам'яті

`LayerManager.clear()` (`:170-178`) робить **тільки** `removeChildren()`. У `render/` єдиний
справжній `destroy` на вузловому об'єкті — `DepartmentBlob.ts:67`.
`OrganizationNodeView` / `PersonNodeView` не знищуються ніде.

`removeChildren` лише від'єднує. Pixi-об'єкти тримають GPU-ресурси до `destroy()`.
Разом із D1: **кожен клік лишає повний набір вузлових ресурсів**.

**Що робити:** `clear()` знищує те, що знімає. Після D1 це рідкісна операція, але коректна вже зараз.

→ **T75** (разом із D1)

## 3. P1 — структура та поведінка

### D4 🟡 `index.ts` став god-object

**Що робити:** `SelectionStore`, `ViewStateStore`, `DataStore`; фасад делегує.

або дати окрему зону, якщо product хоче відокремлений вигляд.

## 4. Порядок робіт

1. **D2** (гонка) — найдешевший; знімає неузгоджений display-list.
2. **D1** (`rebuild` vs `repaint`) — найбільший виграш; після нього D3 не гарячий.
3. **D3** (знищення view) — разом із D1.
4. **D6** (медіа / T74) — паралельно, гілка окрема.
5. **D4** (god-object) — після 1–3, окремим дифом.

## 5. Чого не робити

- Не додавати персистентний кеш зображень у SDK — шар хоста.
- Не прибирати LOD-гейт фото (`PersonNode.ts:273`).
- Не міняти `spine-bus` — збігається з еталоном.
- Не чіпати `Viewport` — життєвий цикл слухачів зроблено повністю.
