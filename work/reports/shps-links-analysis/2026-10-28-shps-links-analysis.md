## 2. Головне питання: чому одні лінії «деп→деп», а інші «особа(деп А)→особа(деп Б)»

Джерело будь-якої лінії — поле `p` (parentId, підпорядкування). **Вид** лінії і **куди вона
впирається** — різні властивості; візуально «деп vs особа» визначає друге.

### Вид (`kind`) — `shps-links.js:108`
```js
const kind = m.d && m.d===c.d ? 'int' : m.d && c.d ? 'cross' : 'ext';
```
- `int` — керівник і підлеглий в одному департаменті (спека §3.1, «внутрішній»);
- `cross` — обидва в департаментах, різних (спека §3.2, «міждепартаментний»);
- `ext` — керівник поза департаментом, тобто `ceo` (спека §3.3, «зовнішній»).

### Куди впирається (`tgt`) — `shps-links.js:105` — **ось залежність**
```js
const tgt=(c,sec)=>{ const cc=cards[c], d=PM[c].d && depts[PM[c].d];
  if(sec) return [cc.x+cc.w/2+SX, cc.y];
  return d && d.head===c ? [cc.x+cc.w/2, d.y1]   // ← у ВЕРХ РАМКИ департаменту (порт deptTop)
                         : [cc.x+cc.w/2, cc.y];  // ← у верх КАРТКИ людини (порт top)
};
```

> **Правило:** лінія впирається в **рамку департаменту** (з кружечком-«входом»,
> `shps-links.js:187`) ⟺ підлеглий є **головою** свого департаменту (`d.head===c`, kind≠int).
> Інакше — у **картку людини**.

Це дослівно спека **§3.2**: «Якщо підлеглий є керівником департаменту B … лінія входить у верхній
центр рамки B … Далі всередині рамки до картки керівника лінія не продовжується». Кружечок —
порт `deptTop` зі спеки §4; легенда мокапу — «Вхід у департамент».

### «Голова» — `shps-links.js:68,74`
```js
const roots = mem.filter(p=>!p.p || !inD(p.p));   // корені: керівник поза цим департаментом
// head = roots[0]  (перший за порядком у POS)
```
Департамент може мати **кілька** коренів (кілька входів ззовні), але рамкою-входом малюється
**лише перший** (`roots[0]`). Решта коренів → у картку людини.

## 3. Класифікація всіх ліній мокапу (за даними `POS`, shps-links.js:3–53)

**У рамку департаменту (виглядає «деп→деп», з кружечком) — рівно 10, по одній на департамент:**

| Департамент | Голова | Керівник голови | kind |
|---|---|---|---|
| Фінансовий | cfo | ceo | ext |
| Продажів | cco | ceo | ext |
| Розробки | cto | ceo | ext |
| Персоналу | hrd | ceo | ext |
| Юридичний | lgl | ceo | ext |
| Служба безпеки | sch | ceo | ext |
| Аналітичний | ah | cfo (Фін.) | **cross** |
| Контролю якості | qh | tlb (Розробка) | **cross** |
| Маркетингу | cmo | cco (Продажі) | **cross** |
| Логістики | lgh | cco (Продажі) | **cross** |

4 з них самі міждепартаментні (`cross`), але все одно йдуть у рамку, бо ціль — голова.
**`cross` ≠ автоматично «в картку».**

**У картку людини «особа(деп А)→особа(деп Б)» — рівно 2:**

| Підлеглий | Його деп. | Керівник | Деп. керівника | Чому в картку |
|---|---|---|---|---|
| `bi` (BI-аналітик) | ana | cto | dev | другий корінь ana (head=ah) |
| `ib` (Фахівець з ІБ) | sec | cto | dev | другий корінь sec (head=sch) |

ana:[ah,bi], sec:[sch,ib] — обидва департаменти мають по два корені; перший → рамка, другий →
картка. Обидві «особа→особа» лінії підпорядковані `cto` (Технічному директору).

Решта: `int` всередині департаментів (завжди в картку, без кружечка); `ext` у картку для
поза-департаментних посад (`asst`←ceo, `aud`←acc).

## 4. Розбіжності спека ↔ мокап лінків (потребують рішення)

**a) §3.2 «один вхід у B + шина» — не реалізовано для не-голови.**
Спека: міждеп. лінія входить у департамент B один раз через верхню межу, далі розгалужується
шиною. Мокап для не-голови веде **кожну** лінію окремо прямо в картку (`tgt`→`cc.y`). Поточні
дані цей кейс не збуджують (нема керівника з кількома підлеглими в одному чужому департаменті),
але це прогалина реалізації. → тестова схема §10.1 п.4.

**b) Подвійне підпорядкування — мокап випереджає спеку.**
Спека §2 і §11-q1: «у цій версії НЕ підтримується / відкрите питання». Мокап **вже** реалізує:
`p2` (єдиний приклад `da`→ceo) як вторинну лінію `sec` у картку зі зсувом `+SX`
(`shps-links.js:112,105`). Фактично відповідь на відкрите питання №1 дана в коді.

**c) Стиль міждепартаментних ліній — мокап випереджає спеку.**
Спека §11-q2: «чи виділяти іншим стилем?» — відкрите. Мокап **вже** дає Tweaks-перемикач
«Міждепартаментні лінії: Як внутрішні / Штрих / Інший колір» (`shps-links.js` + `k-cross` CSS).

**d) Що з інфраструктури мокап уже має (на користь напряму §9):**
A* зі штрафом за поворот (§9.4), коридори+доріжки (§5), обхід перешкод (`deptOK`
`shps-links.js:92`), і **панель статистики**, що перевіряє критерії приймання §10.4 наживо:
перетини / накладання ліній / через картки / ближче 8 px / через чужі деп. + лічильник `fail`.

## 5. card v3 — чому «деп→деп» там інше (reference only)

Немає движка маршрутизації й немає справжніх міждепартаментних ліній. Строго вкладене CSS-дерево
(`.tree`/`.kids` + `::before`/`::after`, card-v3:91–104):
- «особа→особа в деп» = CSS-конектори всередині dept-бокса;
- «деп→деп» = **вкладеність** dept-боксів (конектор від піддерева батьк-департаменту до верху
  дочірніх боксів);
- кейс `bi`/`ib` ця модель **виразити не може** — модель контейнерна.

Саме це обмеження називає спека §9: «Поточний CSS-підхід … годиться лише для простого дерева в
одному контейнері. Для міждепартаментних і зовнішніх ліній його недостатньо». `.plink` у
card v3 = §3.4 (керівна організація→організація, штрих+мітка).

## 7. Невирішене / наступні кроки

- **Показ у браузері не виконано:** розширення Claude-in-Chrome не відкриває `file://`, а підняття
  локального статик-сервера відхилено політикою «Expose Local Services». Варіанти: власник
  дозволяє сервер, або відкриває мокап сам (`! open "…/ШПС лінії зв'язку.html"`) — тоді візуально
  видно, що наведення на `cto` підсвічує дві «особа→особа» лінії (`bi`, `ib`).
- Рішення по §11-q1 і §11-q2 — продуктові (контракт/дефолт), не агентські.
- Якщо йде в роботу реалізація лінків у SDK — звіряти з цим файлом і спекою §3–§10.
