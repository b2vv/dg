## СУДЖЕННЯ (запахи Фаулера)

### S1. Speculative Generality — три з чотирьох гілок блоку 4 стережуть те, чого не було
Спека (T105) просить одного: щоб `*ForTests` не було в барелі. Реалізовано чотири
`problems.push`. Три з них — гіпотези:
```js
} catch {
  problems.push(`${BARREL} не читається — склад публічного барелю неперевірений`);
}
...
if (/export\s+\*/.test(code)) { problems.push(`${BARREL}: зірковий реекспорт …`); }
if (exported.size === 0) { problems.push(`${BARREL}: не знайдено жодного експорту …`); }
```
`export *` у барелі — `grep -c "export \*"` → **0**, і ніколи не було. Нечитний барель ламає
`npm run typecheck` раніше й голосніше. Порожній барель ловиться будь-яким тестом SDK.
`CODING_STANDARDS.md` §0: «якщо SOLID/GoF суперечать KISS на ранньому етапі — перемагає KISS,
поки абстракція не доведена профілем або **другим споживачем**». Другого споживача немає.
Плюс: `export *` тепер **заборонений** машиною, хоча це нормальна TS-ідіома і в жодному
документованому стандарті репо такої заборони немає — гейт вигадав правило, якого нема в мірнику.

### S2. Divergent Change + Mysterious Name — `check:docs` більше не про доку
`scripts/check-docs.mjs` тепер правиться з чотирьох незалежних причин: лінки, покриття
`docs/USAGE.md`, свіжість брифінгу і **склад вихідного бареля**. Четверте — факт про код, не про
доку. Наслідок читається в самому диффі — рядок успіху довелось розтягнути:
```js
console.log('✅ дока свіжа: лінки резолвяться, публічний API описаний, барель без тест-хуків, брифінг у межах');
```
«дока свіжа» і «барель без тест-хуків» — різні твердження під одним іменем. Природний дім для
перевірки — юніт-тест у `packages/sdk` (rstest уже імпортує `../index.js` у
`OrgHierarchyDiagram.test.ts`), де він був би на мові, яку перевіряє, і мав би success/failure.

### S3. Primitive Obsession — конвенція як рядковий літерал
```js
for (const name of [...exported].filter((n) => n.endsWith('ForTests')).sort()) {
```
Доменне поняття «тестовий хук» звелось до суфікса рядка. Сам JSDoc це визнає:
«a hook named `__setLoader` would walk straight past it». Чесно — але це означає, що гейт
захищає **ім'я**, а не **властивість**, і назва проблеми в тексті помилки («тестовий хук
у публічному барелі») обіцяє більше, ніж перевірка може.

### S4. Duplicated Code — парсер бареля дублює те, що знає компілятор
Два регекси відтворюють розбір ES-експортів, хоча репо має `npm run typecheck` і `ttsc-graph`
(`tsconfig.graph.json`), де кожен вузол compiler-resolved. Обґрунтування в JSDoc («`import * as`
бачить лише value-експорти, а в барелі 15 `export type` блоків») пояснює, чому не рантайм —
але не чому не тайп-граф. Дрібний побічний ефект того ж парсера: для інлайнових
`export { X, type Y }` (`packages/sdk/src/index.ts:5`) у набір лягає рядок `"type Y"` разом із
`type`; на `ForTests`-перевірку не впливає, але `exported` — не те, чим себе називає.
Виміряно: 4 таких «забруднених» імені і на `main`, і на `HEAD`.

### S5. Тестові правки — чисто, зауважень нема
`rowTreeDepthGuard.test.ts` / `OrgHierarchyDiagram.test.ts`: `err.name === 'OrgHierarchyError'`
→ `toBeInstanceOf(OrgHierarchyError)`. Це рівно те, що заявляє §15 `docs/USAGE.md`, і імпорт
свідомо через барель із поясненням *чому* — за `CODING_STANDARDS.md` §1 («коментарі пояснюють
чому»). Зауважень нема.
