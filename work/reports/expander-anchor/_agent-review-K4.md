## 🔎 Ваше питання про `if (!org)` — **не самозаспокоєння, але причина інша, і випадок будується**

Ви написали: «через публічний шлях випадок *id невідомий, але діти є* не будується — висячий
`parentOrgId` відсікає `layout/orgTree.ts:22` на прийомі даних».

**Валідатор стоїть не на прийомі даних, а в розкладці.** `validateOrgHierarchy` кличуть
`rowTreeLayout.ts:146` і `:216` та `orgTree.ts:110` — тобто **деревна** розкладка. `setData` і
`create` його не кличуть. А сцена вибирається так: `hasStaff = data.positions.length > 0`
(`DiagramRenderer.ts:422`) — тож **штатна сцена ніколи не валідує org-ієрархію**, і висячий
`parentOrgId` доїжджає до `this.data` цілим.

Виміряно прогоном (тимчасовий тест, видалений після):

```
orgHasChildren(orgs, 'ghost')                    →  true    // другий охоронець НЕ спрацює
create({ data, staffCurrentOrgId: 'o1' })        →  монтується без помилки
getData().some(o => o.parentOrgId === 'ghost')   →  true    // валідатор не бігав
await diagram.toggleOrgExpand('ghost')           →  false   // перший охоронець спрацював
```

Отже `if (!org)` **несе навантаження** в досяжній конфігурації: без нього наступний рядок
дістав би `isOrgCollapsed(undefined)`, тобто `TypeError` замість `false`. І поведінковий тест на
нього пишеться — потрібна лише **штатна** сцена, не деревна:

```ts
organizations: [{ id: 'o1', … }, { id: 'c1', parentOrgId: 'ghost', … }],
positions: [ /* хоч одна, щоб сцена була штатною */ ],
// staffCurrentOrgId: 'o1'
expect(await diagram.toggleOrgExpand('ghost')).toBe(false);
```

**Не блокує.** Коментар у коді чесний у головному (рядок не можна зняти, `tsc` не дасть), і
дефекту тут немає. Але його друга половина — «випадок не будується» — неправдива, і саме таке
речення наступний агент прочитає як доведене. Мінімум: виправити коментар. Максимум: додати цей
тест — він дешевий і закриває останню мутацію, що вижила.

⚠️ Побічне, поза К4: **штатна сцена не валідує org-ієрархію взагалі**. Цикл у `parentOrgId` там
теж не буде спійманий на вході — його ловить лише `walkParentChain` у деревній розкладці. Чи це
дефект — окреме питання (у штатній сцені ієрархія майже не використовується), але як факт воно
не записане ніде.
