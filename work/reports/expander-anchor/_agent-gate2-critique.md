## Лінза 1 — AI-slop

**Чисто по суті.** Перевірено конкретно: (1) чи є абстракція під один виклик — немає, найбільший
новий елемент це один метод фасаду; (2) чи є крок, що переказує очевидне — К1–К8 усі мають
предмет; (3) чи є «на майбутнє» без замовника — навпаки, штатний chevron і якір меню винесені в
out of scope саме за відсутністю замовника.

Два дрібні:

```
[slop] Чекбокс «Тести перед кодом» проставлений ширше, ніж покриває §8
де:      §7, перший рядок
чому:    сказано «кожен крок К1–К6 має тест до реалізації», але К4 (`toggleOrg`) не має в §8
         жодного сценарію на **сам метод** — 16 сценаріїв перевіряють поведінку оверлея й полів,
         а контракт нового публічного методу (невідомий id, лист, що повертає) не перевіряє ніхто
що зробити: або додати сценарій на метод, або звузити чекбокс до «К1–К3, К5, К6»
вага:    non-blocking
```

```
[slop] Нумерація станів у §8 не збігається сама з собою
де:      §8, врізка після таблиці «Три стани відсутності»
чому:    врізка каже «стани 2 і 3 не розрізняються», а рядки таблиці — 3, 4, 5. Це слід від
         `_agent-acceptance.md`, де нумерація була локальна. Читач звірятиме не ті рядки
що зробити: назвати рядки таблиці (4 і 5)
вага:    non-blocking
```

## Лінза 3 — надлишкова складність

**По суті чисто.** Reuse-first таблиця §1 не декоративна: перевірив кожен рядок — `expandOrg`
(`:876`), `collapseOrg` (`:894`), `mountOrgNodeChrome` → `{ expandButton }`
(`orgNodeChrome.ts:135`), `rememberBox` (`DiagramRenderer.ts:884,1053`), `worldBoxToScreen`
(`promoteMath.ts:48`) — усі існують і справді переюзуються.

```
[складність] Ім'я `toggleOrg` ламає ту саму симетрію, якою воно обґрунтоване
де:      §2 Д1
чому:    аргумент за метод — «у штату тогл є, у дерева немає». Штатний зветься
         `toggleStaffOrgExpand`; новий — `toggleOrg`. Симетрія, заявлена як причина існування,
         в імені не виражена, а перейменувати публічний метод після релізу дорожче, ніж зараз
що зробити: `toggleOrgExpand` (або `toggleOrgCollapse`, якщо ближче до `collapsed`) — вирішити до К4
вага:    non-blocking
```

```
[складність] Сигнатура нового публічного методу в плані не названа
де:      §2 Д1, §3 К4
чому:    єдина нова поверхня циклу, і про неї відомо лише ім'я. Штатний близнюк повертає
         `Promise<boolean>` (новий стан). Якщо новий поверне `Promise<void>`, симетрія
         зламається вдруге, а оверлей не матиме як дізнатись результат
що зробити: зафіксувати `toggleOrgExpand(orgId: string): Promise<boolean>` у плані, а не на
         етапі коду
```

## Лінза 4 — edge cases

```
[edge] `toggleOrg` успадковує шлях БЕЗ транзакції — і клік це fire-and-forget
де:      §2 Д1, §3 К4/К5
чому:    `expandOrg` (`:876`) і `collapseOrg` (`:894`) кличуть `render()`, **не**
         `drawOrRestore`, і шлють `onOrgModeChange` **до** кадру — тобто вони поза дисципліною
         T104/T109 (порівняй `revealPath:1396-1413`, який відкочується). Клік з оверлея — без
         `await` (`createTestAnchorOverlay.ts:86` — `void diagram.…`), тож впалий рендер стане
         **необробленим reject** у сторінці хоста. Фасад уже має протилежний зразок для
         fire-and-forget жестів: `.catch` довкола `reparentPosition` (`:775-786`)
що зробити: або обгорнути гілку кліку `.catch` за наявним зразком, або свідомо прийняти й
         записати; і назвати, чи `toggleOrg` іде через `drawOrRestore`
вага:    🔴 blocking
```

```
[edge] Якір експандера лежить УСЕРЕДИНІ якоря картки, а z-порядок вирішує порядок у DOM
де:      §3 К5
чому:    оверлей не ставить `zIndex` на окремі якорі — усі абсолютні `<button>` у одному шарі
         (`createTestAnchorOverlay.ts:63-80`), тож перекриває той, що доданий пізніше. Якщо якір
         кнопки додати **перед** якорем свого вузла, клік по ньому перехопить картка — і A9
         впаде на «element intercepts pointer events»
що зробити: один рядок у К5: якір експандера додається **після** якоря свого вузла
вага:    non-blocking — перший же тест К5 (сценарій 1) червонітиме голосно, а не тихо
```

```
[edge] Невідомий id і лист: що робить `toggleOrg`
де:      §2 Д1
чому:    `expandOrg` на невідомому id — тихий no-op плюс рендер плюс `panToNode`, який не
         знайде бокса. Для нового публічного методу це треба назвати, бо хост його викличе
         з тестового коду з довільним рядком
вага:    non-blocking
```

```
[edge] Клік по якорю рухає камеру — і це не сказано в сценаріях 1/2
де:      §8, сценарії 1, 2, 9
чому:    `expandOrg` завершується `fitView` (matrix→row-tree) або `panToNode(..., animate:true)`
         (`:886-891`), `collapseOrg` — теж `panToNode`. Тобто після кліку **всі** якорі
         переїжджають, і e2e, який одразу міряє координати, читатиме анімацію. Це готове
         джерело саме того флаку, який сьогодні виміряно (3 падіння з 15, усі — про час)
що зробити: у сценаріях 1/2/9 явно чекати на осідання камери, а не на появу дітей
вага:    non-blocking
```

```
[edge] Пара «якір вузла + якір кнопки» не гарантована
де:      §3 К5
чому:    оверлей викидає якорі поза екраном поштучно (`:60`, `screenRectInView`). Картка може
         бути видима, а кнопка — за краєм, і навпаки при частковій видимості. Тест, що очікує
         обидва або жодного, флакатиме на певних зумах
вага:    non-blocking
```
