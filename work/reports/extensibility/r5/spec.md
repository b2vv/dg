# R5 — Мультивибір: marquee (rubber-band) — spec

**Статус:** spec. Гілка `feat/extensibility`. Джерело: ROADMAP R5 + «північна зірка». GATE-1 з роадмапу.

## Проблема / межа
**Shift-клік toggle ВЖЕ Є** (`personInteractions.ts:161-163`, `orgCardInteractions.ts:53-57` → `handlePointerSelect`
з mods → InteractionStore toggle). Отже R5 ≠ shift-клік. **Бракує marquee (рамки):** протягнути прямокутник на
порожній сцені → вибрати всі ноди, чий **box перетинає** прямокутник (ROADMAP R5). Власник: **SDK = логіка вибору +
marquee-hit-test за геометрією; хост = лише стилізація прямокутника** (презентація гумки інжектована).

## User scenarios (рев.2 — marquee = Shift+drag, завжди additive)
1. Користувач тисне **Shift + порожнє місце** й тягне → зʼявляється рамка (стилізація хоста) → по відпусканні ноди,
   чиї бокси перетинають рамку, **додаються (Shift-union)** до поточного вибору (`InteractionStore`, Shift-union).
2. Рамка — це multi-select-жест (роадмап-легенда «Shift-клік **або рамка** — мультивибір»): вона **додає**, не замінює.
   Щоб почати з чистого — клік на ноду (replace) або клік на порожнє (зняти), тоді Shift+рамка.
3. Звичайний (без Shift) drag на порожньому = **пан камери, незмінно**. Клік на порожнє без руху → знімає вибір, як зараз.
4. Хост малює прямокутник власним стилем (SDK дає world-геометрію рамки через колбек `onMarquee`), не рахує вибір.

## Acceptance (чернетка)
- AC1: drag на порожньому → по відпусканні `selected` = ноди, чиї world-бокси перетинають world-рамку (Shift-union).
- AC2 (рев.2): marquee (= Shift+drag) **завжди additive** — додає перетнуті ноди до поточного вибору, ніколи не
  замінює (replace-гілки нема, бо без Shift drag = пан). Replace робить клік на ноду; зняти — клік на порожнє.
  ⚠️ «marquee не може очистити вибір» — свідоме рішення (роадмап-легенда «рамка=мультивибір»); винести власнику.
- AC3: hit-test — **перетин** box×rect (не «повністю всередині»), за геометрією (world-бокси нод), не DOM.
- AC4: порожній клік без суттєвого руху (< поріг) → не marquee; поведінка зняття вибору як зараз.
- AC5: SDK емітить геометрію рамки (start/current world-rect) для стилізації хостом; хост не рахує вибір.
- AC6 (**рев.2, opt-in — урок D1**): повний marquee (жест+вибір+візуал) активний ЛИШЕ коли хост дав `onMarquee`.
  Без `onMarquee` — Shift+drag поводиться як зараз (пан), 0 змін (байт-у-байт). (Виправляє суперечність зі старим AC6.)
- AC8 (**рев.2, F1 gesture**): тригер marquee = **Shift + лівий-drag на порожньому** (роадмап R4-легенда: «Shift — вибір;
  рамка — мультивибір»). Звичайний (без Shift) лівий-drag = пан камери, НЕЗМІННО. Пан гаситься лише для Shift+drag і
  лише коли marquee активний (onMarquee заданий). ⚠️ Рішення моделі жестів — роадмап-grounded; винести власнику на огляд.
- AC7: 0 вартості в спокої (жест лише під час drag); селекція через той самий InteractionStore (сумісність onSelectionChange).

## Out of scope / Open
- Shift-клік toggle — вже є (R5 лише перевіряє, що marquee співіснує, не ламає).
- **Open (план):** (а) шов рамки до хоста — колбек `onMarquee(rect|null)` чи інжектований renderer? (рекоменд.: колбек
  world-rect, хост малює; симетрично promote-overlay); (б) поріг «клік vs drag» (px); (в) hit-test на far-LOD боксах
  (geometry завжди є) — рамка працює на всіх LOD; (г) emphasis/hover під час marquee — не чіпати.
