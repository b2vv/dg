## Блокувальні

### Б1. Розмір картки як «вхід» не працює на шляху alpha — SDK бере один розмір на всю організацію
Документ (§2 рядки 23, 28, 47–49, §4 рядок 144, DoD рядок 167) стоїть на тому, що хост подає
калібрований розмір кожної картки через `nodeSizes`/`position.width|height`, а Rust розкладає з нього.
Це правда для старого staff-шляху (`buildStaffLayoutInput.ts:41-46`), але **еталон — staff-alpha**,
а там розкладка йде через `staffAlphaMockup` → `buildStaffMockupInput`
(`packages/sdk/src/render/staffLiveGeometry.ts:327-351`):
- `seatW = inOrg[0]?.width ?? 300`, `seatH = inOrg[0]?.height ?? 112` — розмір **першої** посади
  організації застосовано до всіх; `nodeSizes` цей шлях не читає взагалі;
- Rust-параметр — один `cardWidth`/`cardHeight` (`StaffMockupParams`).

Наслідок: «дискретні класи висоти під Onest» (ADR-0079 §3) на alpha не мають ефекту, крім першої
картки. Контроль проби з рядка 76 це **зловить** (зміщена не-перша картка не зрушить сусідів) — тобто
проба правильна, а план під неї зараз не виконується.
**Виправлення:** рішення (власника) — (а) alpha лишається з єдиним розміром картки (мокап v3 —
однакові 300×113), і тоді ADR-0079-класи висоти для ШПС не потрібні, хост подає один розмір; або
(б) SDK вчить mockup-розкладку поважати розмір кожної картки — це робота моєї смуги в Rust. Поки
не вирішено, DoD-рядок 167 не досяжний.

### Б2. «Alpha в хості» за зразком демо переносить у хост геометрію, яку забороняє інваріант
Документ (рядки 38, 54, 112) бере демо за зразок host-overlay і вважає, що там лише рендер із
SDK-геометрії. У демо це не так — воно саме рахує геометрію:
- **рамка організації** — AABB по рамках відділів і картках з константами `PAD = 20`, `TOP = 44`
  (`packages/demo/src/app/StaffChromeBackdrop.ts:104-131`) — це layout-математика;
- **fit** — `staffFitTransform` (`StaffChromeBackdrop.ts:209-221`: центрування й масштаб із бокса)
  плюс твін камери в `App.ts:761` `refitStaffAlpha`;
- **друге обчислення геометрії** — демо окремо кличе `computeStaffLiveGeometry` (`App.ts:707`)
  паралельно з тим, що SDK рахує сам у `setData`. Поки входи збігаються, збігаються й координати;
  хост, що подасть різні входи в два виклики, отримає два джерела координат — клас reset;
- **world→screen на кожен елемент** у backdrop (`StaffChromeBackdrop.ts:341+`, `px = n*s`,
  `worldPointToScreen`) — саме те «перемноження px», яке документ помітив у рядку 78.

Межа лінт-гейта з рядка 39 («layout заборонено, viewport-композиція дозволена») не покриває перші три
пункти, бо вони не схожі на «layout» за назвою.
**Виправлення (моя смуга, без «alpha в публічне API» — картка/пошук лишаються в хості):**
1. SDK віддає геометрію **свого ж** останнього рендера — рамки відділів, рамку організації, маршрути,
   бокси карток — у `PromoteBackdropProps` або getter-ом, щоб хост не робив другого виклику й AABB;
2. backdrop-шар SDK отримує камерний CSS-transform, щоб хост малював у світових одиницях без `·scale+pan`;
3. `fitView` отримує опції `minScale`/`maxScale`/вирівнювання по верху (і анімацію), щоб fit v3 був
   викликом SDK, а не формулою в хості.
Після цього лінт-гейт може бути простим: жодного `scale` / `viewport.x` у `modules/positions`.

## Неблокувальні

- **Н1. Застаріле після `1150ae6`.** B3 виконано: `nodeCenter`/`nodeCanvasPoint`/`expanderCenter`,
  `onNodeClick` з модифікаторами, `payload`, `request.incomingLink` — на гілці
  `feat/sdk-host-geometry-seam` @ `1150ae6` (а не `feat/t126-staff-rust-geometry` @ `0e737de`, рядки 8,
  10). Рядки 38, 164, 168 досі кажуть «нема». За власним правилом документа (рядок 39: «коли додані —
  навіть ця композиція зникає») тимчасовий дозвіл на viewport-композицію треба **прибрати** зараз,
  інакше гейт піде з винятком, якому вже немає причини.
- **Н2. Суперечність:** рядок 150 «за рішенням власника — alpha в публічне API» проти рядка 53
  («alpha в хості, вирішено»). Рядок 151 «після critique» — уже відбулось.
- **Н3. Тихий фолбек розміру хибний для ШПС.** Рядок 92: відсутній розмір → SDK-дефолт
  `nodeWidth/nodeHeight`. Дефолт — **136×156** (`layout/staff/types.ts:70-71`), а не 300×113; на alpha —
  300×112 (Б1). Тобто картка без розміру мовчки стане іншою. Краще fail-loud у мапері: кожна посада
  отримує розмір, тест рахує, що їх стільки ж, скільки посад.
- **Н4. Гонка в демо, яку не варто копіювати.** `rerenderStaffAlpha` (`App.ts:725-745`) робить два
  async-кроки (геометрія хрому, потім `setData`) без лічильника поколінь; при швидкому подвійному
  тоглі старіший обчислений хром може лягти після новішого. А `catch` лишає **старий** хром при новому
  `setData` — рамки від однієї розкладки, картки від іншої. Пункт Б2.1 прибирає це разом із другим
  викликом.
- **Н5. `preserveViewport`.** Рядок 94 спирається на `setData(…, {preserveViewport})`. У SDK такої
  опції немає: `setData` камеру не чіпає взагалі, рефіт — окремий виклик. Адаптер мапить
  `preserveViewport: false` → fit. Правило «виграє останній» — задокументоване, `docs/USAGE.md` §11
  «Хто виграє, коли `setData` викликано двічі поспіль» — краще послатись, ніж стверджувати.
- **Н6. Геометрію можна перевіряти автоматично.** Рядки 71, 159 кажуть, що хост координат не міряє.
  Це правда для jsdom, але не для живого Playwright (`E2E_LIVE`): там справжній layout, а з `1150ae6`
  є `nodeCenter`. Ручний гейт «батьки по центру дітей» і контроль проби з рядка 76 можна зробити
  живою спекою: `nodeCenter(parent).x ≈ середнє nodeCenter(children).x`, і зміщений розмір рухає сусіда.
  Саме цей клас провалу знесли — лишати його лише на око ризиковано.
