# План Б1 — alpha-розкладка (mockup) з розміром на картку

Рішення власника 2026-11-02 (через Cass-1): розмір картки ШПС — **на картку** (варіант б рецензії
`_review-design-doc-cass-2026-11-02.md` Б1). ADR-0079 хоста: хост калібрує класи висоти під Onest і
подає їх входом; ширина в хоста 300 const.

## Що зараз
- TS `packages/sdk/src/render/staffLiveGeometry.ts:327-351` `buildStaffMockupInput`: `seatW/H =
  inOrg[0]?.width/height ?? 300/112` — один розмір на всю організацію.
- Rust `packages/core/src/staff_mockup_layout.rs`: `StaffMockupParams.card_width/card_height` —
  скаляри; 47 використань `cw/ch` у tidy-tree (`subtree_width`, `place_within`, висота рамки
  `:1408`, singleton `:1426-1427`, ноди `:1525`) і в роутері (`edge_target`, шина `build_edges
  :497/:509`, `build_grid :610-664`, `astar :837`, `stats_core :1049`, `route_simple :1094-1096`,
  `route_astar :1128-1129`, `mockup_stats :1248`).

## Вхід
`StaffMockupInput.sizes: Vec<StaffNodeSize>` (`#[serde(default)]`, наявний тип `{id,width,height}`).
Картка без запису → `params.card_width/card_height`. TS заповнює `sizes` з **публічних**
`DiagramPosition.width/height` кожної посади (не `nodeSizes`: той не має публічного шляху з фасаду);
`params.cardWidth/Height` = 300/112 як фолбек. `inOrg[0]` прибрати.

Валідація: `width/height` скінченні й > 0, інакше `Err` (як `validate_layout_metric` у `types.rs`),
а не тихий фолбек.

## Семантика (закладається, повідомлено Cass-1)
1. `subtree_width`: ширина листа = ширина **цієї** картки.
2. Рядки у відділі: рівень = глибина в дереві відділу (від кореня відділу). `row_h[level]` = max висот
   карток цього рівня **в цьому відділі**. `row_top[0]=0`, `row_top[k]=row_top[k-1]+row_h[k-1]+lv`.
   Картка: `y = dpt + row_top[level]` (вирівнювання по верху), `x = x0 + (wid - w(id))/2`.
3. Висота рамки = `dpt + Σ row_h + (depth-1)·lv + dp`.
4. Singleton-блок: `w/h` своєї картки.
5. Роутер: усі `cw/ch` → `w(id)/h(id)` картки; шина Int (`:497`) = `y(m) + row_h(m) + lv/2` — під
   **низом рядка** менеджера, не під низом його картки; Ext (`:509`) = `y(m) + h(m) + bv/2` (singleton:
   рядок = картка).
6. `StaffMockupNode.width/height` = розмір картки.

## Інваріант регресії
Однакові розміри → **байт-у-байт** той самий `StaffMockupResult`, що до зміни (наявні 7 Rust-тестів і
TS-тести alpha не міняються; golden-порівняння «до/після» на фікстурі демо).

## Тести (спершу червоні)
- Rust: (а) рядок вирівняний по верху, наступний рівень під найвищою карткою рівня; (б) вища картка
  розсуває рамку відділу; (в) ширша картка розсуває сиблінгів (subtree_width); (г) шина Int під низом
  рядка, а не під низом нижчої картки менеджера; (д) `stats()` over/near/dept == 0 на змішаних
  розмірах (фікстура демо з різними висотами); (е) невалідний розмір → Err; (є) рівні розміри ==
  результат зі скалярними params (регресія).
- TS: `buildStaffMockupInput` несе `sizes` з `position.width/height` кожної посади; посада без
  розміру — немає запису (фолбек у Rust); контроль: зміна висоти **не першої** посади рухає сусіда в
  `computeStaffLiveGeometry`.

## Поза межами
Б2 (геометрія рендера в props, камерний backdrop, fitView-опції) — чекає рішення власника.

## Після критика (`_critique-b1-per-card-size.md`, gate-reviewer Opus 4.8) — правки плану
- **Б1 (шина Int):** шина = `y(дитини) - lv/2` — верх рядка дитини мінус пів-gap; усі діти рівня
  вирівняні по верху, тож це те саме, що «низ рядка менеджера + lv/2», без нового поля в `RouteInput`.
  На рівних цілих розмірах числа збігаються з поточною формулою.
- **Б2 (тести, що зелені без фічі):** (г) фікстура з менеджером **строго нижчим** за сусіда свого рядка;
  (є) регресія — проти **збереженого до зміни** golden (`8daa0a5`, `tests/fixtures/mockup-golden-*.json`),
  не новий-код-проти-нового-коду; (д) гейт `stats()` валідний лише після переводу `stats_core` на
  розмір на картку — переводимо в тому ж зрізі.
- Н1: `subtree_width` клампить **кожен** вузол до `w(id)`, не лише лист.
- Н2: «байт-у-байт» обіцяємо лише для golden-фікстур (цілі розміри), не для довільних f32.
- Н3: дублікат id у `sizes` → `Err`; записи для посад поза входом ігноруються.
- Н5: точки правки сигнатури `stats_core` — repair-loop `:1190` і `mockup_stats :1248`.
