# D0 — spike: механізм перетинів на <100 (dg41)

**Мета (plan.md rev.3 §3 D0):** закріпити, ЯКІ ребра дають 4 перетини на 99-сцені й чому; partial-cohort
конструктор для пошуку першого `cross>0`; операційний критерій router-vs-layout. Без продакшн-змін
(інструментація лише в `mod tests`, revert-proven; goldens недоторкані).

## 🔴 ГОЛОВНА ЗНАХІДКА — гіпотеза cap→fallback СПРОСТОВАНА на <100

Інструментація (test-only, additive `failed_edges` у `RouteObservation` + `cross_pairs` + partial-cohort конструктор;
продакшн байт-ідентичний HEAD; `cargo test --release -- --ignored d0_pin_crossings`):

```
99-scene quality: cross=4 over=0 card=0 near=0 dept=0
failed (fallback) ast edges [0]: []          ← ЖОДНОГО fallback!
raw segment crossings: 4
  [ah-1->da-1]   X  [ceo->da-1]       (обидва fallback=false)
  [ceo->da-0]    X  [cfo-0->ah-0]     (обидва fallback=false)
  [ceo->da-1]    X  [cfo-0->ah-0]     (обидва fallback=false)
  [cto-0->ib-0]  X  [cto-1->bi-1]     (обидва fallback=false)
every crossing involves >=1 fallback edge? false
```

**Висновок:** на 99 посадах A* НЕ капиться (0 failed edges) — усі 4 перетини між **успішно зароутеними** шляхами.
Історія `cap → fallback пряма лінія → перетин` (з `_codex-capdiag-dg41.md`) — це феномен **масштабу 491**, а НЕ
механізм на цільовому <100. На <100 двигун роутить успішно, але **per-edge незалежний A* + 5 repair-пасів не
гарантують 0 перетинів**: occupancy-штрафи відштовхують маршрути, але не забороняють перетин, і repair ці 4 не зняв.

Наслідок для §0 плану: при <100 вартість 694ms@99 — це НЕ cap-шторм (0 капів), а маски `build_grid` + завершені
A*-пошуки по решітці 746×132 × 16 ast × 5 пасів. Два болі (perf і якість) на <100 **розчіплюються**: perf = маски,
якість = незавершеність repair/незалежність маршрутів.

## Ребра-джерела (хто з ким перетинається)
Усі — крос-деп / вторинні, що сходяться в одному регіоні (аналітика `da`/`ah`, центральний `ceo`):
- `ceo→da-k` (вторинний віяловий фан центр→аналітика) × `cfo-0→ah-0` і `ah-1→da-1` — конкуренція за регіон `ah`/`da`;
- `cto-0→ib-0` × `cto-1→bi-1` — крос-деп лінії двох когорт перетинаються між собою.

## First-crossing sweep (50→99, indicative, N5 — partial рве цілісність reports)
```
positions=50 cross=0
positions=60 cross=0
positions=70 cross=0
positions=80 cross=5   ← перший cross>0
positions=90 cross=5
positions=99 cross=4
```
Перетини з'являються ~80 посад (1 повна когорта + ~30 другої), коли крос-деп ребра ДРУГОЇ когорти починають
конкурувати з першою. Немонотонність 5→4 — артефакт часткової когорти (N5), число лише орієнтовне.

## 🔴 Доказ router-vs-layout (схвалено власником): repair-пас-світп — ЗАСТРЯГ

Репліка production-роутингу з параметром кількості repair-пасів (`route_npass`, дзеркало `observed_routes`
через продакшн `astar`; self-валідація: `route_npass(4) == production cross = 4` ✓):

```
passes=4  cross=4
passes=8  cross=4
passes=16 cross=4
passes=32 cross=4
passes=64 cross=4
```

**Вирішальний висновок:** більше перемаршрутизації **НЕ** знімає 4 перетини — застрягло на 4 за будь-якої кількості
пасів. Отже проблема **не** «замало пасів». Поточний repair (перемаршрутизація по ОДНОМУ ребру + soft-штраф
foreign +6000) структурно **не здатен** вийти з цього локального мінімуму: ці 4 — **взаємні/симетричні** конфлікти
(напр. `cto-0→ib-0 × cto-1→bi-1` — дзеркальні dev→аналітика лінії двох когорт; `ceo→da` фан × `cfo-0→ah-0`).
Перемаршрутизація одного ребра лише зсуває конфлікт на інше.

**Що це доводить і що ні:**
- ВИКЛЮЧЕНО: cap→fallback (0 fallback) і «замало пасів» (64 паси = ті самі 4).
- ДОВЕДЕНО: потрібна **ІНША стратегія роутингу** (спільне/глобальне планування, спільні коридори для родин
  крос-деп ребер, або роутинг із забороною перетину) — а не більше того самого greedy-repair.
- ЩЕ НЕ ДОВЕДЕНО (вхід у D1): чи має layout місце для БУДЬ-ЯКОГО неперетинного роутингу.

## Hard-block існування (схвалено власником) — НЕКОНКЛЮЗИВНО, але інформативно

Конструктивна спроба: зароутити ВСІ ast-ребра жадібно з `astar_hardblock` (перетин = жорстка стіна: foreign-overlap
+ перпендикулярний перетин через вузол заборонені).

```
hard-block routing (crossing forbidden): fallbacks=4  residual_cross=26
```

**Результат — протилежний очікуваному:** заборона перетину в ЖАДІБНОМУ один-прохід дала 4 fallback (прямі лінії) і
cross **26** (гірше за 4). Тобто наївна заборона перетину не працює: пізні ребра в жадібному порядку знаходять усе
заблокованим ранніми → падають у fallback → прямі лінії перетинають ще більше.

**Що це доводить і що ні (чесно):**
- fallbacks>0 ⇒ hard-block **НЕ сконструював** неперетинний роутинг ⇒ існування **НЕ доведено**.
- Але це **порядко-залежний жадібний** провал — НЕ доказ, що неперетинного роутингу не існує глобально.
- Разом із repair-світпом (soft-penalty теж застряг): **ОБИДВІ жадібні стратегії** (production soft-penalty і
  hard-block) не дають неперетинного роутингу. Це сильно вказує, що потрібне **глобальне/спільне планування**
  (коридори/ILP-подібне), а не локальний per-edge роутинг.
- 🔑 **Висновок про метод:** router-vs-layout **не відокремлюється дешевими жадібними зондами**. Єдиний доказ
  існування — **побудувати** глобальну/коридорну модель і перевірити, чи дає вона cross=0 на 99. Отже це питання
  **за своєю природою належить D1**: прототип моделі D1 сам є тестом існування (дає 0 → layout має місце
  конструктивно; не дає → layout причетний). Окремого дешевого доказу перед D1 немає.

## Критерій router-vs-layout (plan §3 D0 N1) — ПЕРЕУТОЧНЕНО
Бінарний критерій «це fallback?» повернув **ні** — отже проста розвилка «cap→fallback» не застосовна на <100.
Справжнє питання на цілі: **repair-too-weak vs layout-too-tight**:
- (router/repair) маршрути завершені, недетермінований/жадібний порядок per-edge + лише 5 пасів repair лишають 4
  перетини, які РОЗВ'ЯЗНІ перемаршрутизацією (ЩЕ не доведено — треба перевірити, чи існує неперетинна ортогональна
  альтернатива для цих 4 ребер);
- (layout) `ceo`/`da`/`ah` розміщені так, що неперетинного ортогонального маршруту для цих ребер НЕ існує в наявному
  каналі → фікс у spacing/placement (ADR-0002), не в роутері.
D0 **звузив** питання, але не закрив його: наступний доказ (чи існує неперетинна альтернатива для 4 ребер) — вхід у D1.
