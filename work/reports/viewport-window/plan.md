## 3. Кроки

Порядок підпорядкований Р8 **по-справжньому**: усе, що вимір може скасувати, стоїть після виміру.

### Етап 1 — наскрізна смуга на наявному API

0. **Відновити стенд і зняти базу.** `e2e/t87-motion.spec.ts` з `7b79211`. Зняти дофічеві
   p50/p95 на `Staff · 1M` (жест N екранів, програмний WebGL) — **до першої правки коду**,
   інакше рядок 22 нічим закрити. Число в звіт.
1. **Абсолютна сітка staff.** `currentTier`: `col = i % STAFF_SCALE_COLS`,
   `row = floor(i / STAFF_SCALE_COLS)`; голова блоку й `reportLines` не залежать від `range.start`.
   Без цього кроку решта етапу не має на що спертись.
2. **Публічний колбек камери.** `onViewportChange?(t: ViewportTransform, meta: { settled: boolean;
   reason: 'camera' | 'resize' })` у `callbacks.ts`, вішається на `PixiHost.setOnViewportChange`
   **і** на `setOnResize` (У4 — ресайз міняє, скільки влазить, не рухаючи камеру).
   rAF-коалесцування і settle-таймер будуються тут, у `OrgHierarchyDiagram`; `requestPaint`
   коалесцує лише малювання і для цього не годиться.
   Тіркдаун: `destroy()` знімає підписку й гасить таймер.
3. **Вікно в демо на `setData`.** Підписка → екранний прямокутник → діапазон індексів
   (`windowSize` **похідний** від `reserveScreens` × геометрії в'юпорта, не константа 600) →
   `buildScaleStaffWindow` → `setData`. Серіалізація: поки одна перебудова в польоті, наступна
   ставиться в чергу, проміжні відкидаються (остання виграє).
   **Деградація, коли перебудова не вдалась** (воркер упав, WASM-розкладка кинула, `setData`
   зареджектив): сцена лишається на **попередньому** вікні — не порожніє; статус називає
   причину; черга скидається, щоб наступний жест не застосував протухлий діапазон.
   Мовчазний реджект заборонений тим самим правилом, що й мовчазна порожнеча.
4. **Спостережуваний сигнал.** Статус `window <start>…<end> / total` + `data-window-start`
   на монтуванні. Без нього e2e рядків 1, 2 спатиме на константі (N15).
5. **Стрибок `pos-N` без `reload()`.** Переводиться на той самий шлях: `setData` замість
   `disposeDiagram() + create()`. Інакше рядок 16 недосяжний за побудовою (З7).
6. **Вимір — гейт для всього далі.** `reserveScreens`, поріг перебудови, ціна `setData` на вікні
   в мс, окремо **з перекриттям id і без** (З9: перекриття вмикає повну `rebuildForScale`).
   Порівняння з базою кроку 0.

### Етап 2 — пошук (Р5, рішення користувача)

7. `searchBeyondWindow?(query, page): Promise<{ hits, total, hasMore }>` — `total`, а не лише
   `hasMore` (З8: рядок 13 вимагає число). Плюс три речі, без яких колбек неповний:
   - **матеріалізація хіта до фокуса**: `revealPath` повертає `false` для id поза `this.data`;
   - **правило «остання виграє»**: відповідь, що прийшла після нового запиту, відкидається;
   - **`destroy()` під час await**: перевірка після await, не лише перед ним;
   - **кривий пейлоад**: колбек — це чужий код, тож відповідь валідується перед вживанням
     (не масив, відсутній `total`, `hits` не тієї форми) і трактується як відмова, а не як
     «нуль збігів» — інакше помилка хоста виглядає для користувача як «нікого не знайдено».
   Форма повернення `search()` розширюється — це **не адитивна** зміна (див. §5).

### Етап 3 — умовні кроки (входять лише за числами кроку 6)

8. **Скелетони.** Умова входу: вимір показав видиму порожню смугу.
   Перший варіант — **хостовий оверлей** на публічних `worldBoxToScreen` / `screenRectInView`;
   origin блоку береться з `listPromoteBoxes`, решта — з абсолютної сітки кроку 1.
   Стеля числом: не більш ніж N боксів, понад неї — суцільна заливка (У5).
   Власник гасіння: наступний успішний `setData` очищає оверлей; гілка помилки — явно (N13).
   Шар у SDK — лише якщо оверлей не витягує кадр.
9. **`spliceData`.** Умова входу: вимір показав, що `setData` на вікні не вкладається в бюджет
   кадру. Тоді ж вирішується форма — новий метод чи опція `setData` — і тоді ж доведеться
   розв'язати те, що `setData` закриває безкоштовно: видалення ребер без id (З1), прунінг
   виділення й розгорток (З10), гонка індексу (З9), інкрементальний білдер у демо.
10. **Blur.** Умова входу: вимір показав, що запас не закриває швидкий жест.
    Двостановий, гістерезис (Р2). Якщо не входить — A6 закривається записом у звіті
    «blur не реалізовано, підстава — число X мс» (N9).

### Поза цим циклом

11. **100k** — окрема T-задача. Умова входу: числа A2/A3 з етапу 1. Там же вирішується, **хто**
    зрізає позавіконні `parentOrgId` — генератор чи пом'якшення `validateOrgHierarchy`
    (`orgTree.ts:19-24` кидає навмисно, `matrixLayout.test.ts:86` це фіксує), і що з
    `matrixOrder: i - start`, який теж віконно-відносний.

## 5. План міграції

Міграції даних немає. Міграція API:

1. `onViewportChange` і `searchBeyondWindow` — адитивні опційні колбеки.
2. **`search()` міняє форму повернення** — єдина неадитивна зміна. Виходить разом із
   `docs/USAGE.md` тим самим комітом (Конституція).
3. `docs/USAGE.md` §11 доповнюється: `setData` як шлях суванння вікна вже описаний, додається
   лише колбек камери.

## 6. Rollback

Незворотних ефектів немає: ні міграції даних, ні зовнішніх викликів, ні записів у сховище.
Найгірший наслідок відкату — демо повертається до сьогоднішньої поведінки (`pos-N` через
`reload()`, вікно не їде). Кроки 0–6 і 7 відкочуються revert'ом; кроки 8–10 можуть не існувати
взагалі, якщо вимір їх не впустить.

## 7. Конституція

| Рядок | Проведення |
|---|---|
| Тести перед кодом | кожен крок через `tdd`; кроки 1, 3 — чисті функції, тестуються без Pixi |
| KISS → SOLID → … | **спрацював двічі**: відхилено механізм вікна в SDK (GATE 1) і `spliceData`/скелетони до виміру (GATE 2). Абстракція не вводиться без профілю або другого споживача |
| GoF за ≥2–3 повтореннями | патернів не вводиться |
| Межа WASM↔TS | **не зсувається**: `types.rs` не чіпається, регенерація `rust-types.ts` не потрібна |
| Публічний API не мовчки | §5 п. 2 — `USAGE.md` тим самим комітом |
| Pocock лише TS | увесь дифф — TS |

⚠️ **Свідомо прийняте відхилення від рекомендації:** Р5 (колбек пошуку в SDK) вводить публічний
член заради споживача, якого сьогодні немає — рівно те, від чого застерігає рядок KISS. Рішення
користувача, зафіксоване; ціна названа в кроці 7.

## 9. Захист плану (`plan-defense`)

П'ять фіксованих питань. Дві дірки, знайдені прогоном, закриті правками плану (не відповіддю
в чаті) — рядки, що їх закрили, названі нижче.

| # | Питання | Закрито рядком | Вердикт |
|---|---|---|---|
| 1 | кривий інпут | §3 крок 7 (валідація пейлоада колбека) + §8 рядки 20, 24 | закрито — **була дірка**, дописано |
| 2 | відмова залежності | §3 крок 3 (деградація при відмові воркера/WASM) + §3 крок 7 (колбек: кинув/повільний/destroy) + §8 рядки 16, 18, 19, 23 | закрито — **була дірка**, дописано |
| 3 | гонка й повторний виклик | §3 крок 3 (серіалізація, остання виграє) + §8 рядки 9, 15, 22 | закрито |
| 4 | порожні та граничні дані | §8 рядки 5, 6, 7, 10, 12 | закрито |
| 5 | rollback | §6 цілком | закрито |

**Дірок лишилось: 0.** Гейт зелений.

Прим. до рядка 4: дублікати як окремий випадок **зникли зі скоупу** разом із перенесенням
`spliceData` в умовні кроки — `setData` замінює вікно цілком, тож стану «той самий id двічі»
не існує за побудовою. Якщо крок 9 колись увійде, це питання перевідкривається разом із ним.
