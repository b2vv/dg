## 🔴 ДВА КОРЕНЕВІ МЕТОДОЛОГІЧНІ РОЗБІЖНОСТІ

**#1 LAYOUT — де стоїть ana (чому в нас довгі лінії й перетини):**
Мокап ставить ana ПІД fin і НИЖЧЕ неї (ah прямо під cfo) → cfo→ah = коротка майже-вертикаль. Наш — ana праворуч
біля dev (ah на 5586, cfo на 1322) → cfo→ah = детур через пів-полотна (аж на x=−26) → ріже віяло ceo = перетини.
Причина: мокап обирає head мульті-джерельного деп = ПЕРШИЙ root у порядку POS (ah→cfo→fin); наш — інакше
(ana опиняється біля dev). + мокап нести дочірній деп-блок ВЕРТИКАЛЬНО під батьком.

**#2 ROUTING — чому мокап-лінії РІВНІ, а наші зигзаги (ГОЛОВНЕ):**
Мокап роутить ІЄРАРХІЮ (42/50 ребер: усі ceo→діти + внутрішньодеп) ДЕТЕРМІНОВАНИМИ елбоу на спільній шині
(mid-gap), РЕЗЕРВУЄ їх ПЕРШИМИ, і лише 8 справжніх cross/secondary ребер A*-ить В ОБХІД. **Ми A*-имо ВСІ 50
ребер** → кожне шукає свій шлях → джоги, бампи, детури. Саме тому наша «рівна шина» раніше впала (ми не мали
det/ast-поділу й не резервували елбоу першими).

## ВИСНОВОК (вхід у правильний переробіток)
Наш parent-eval (брутфорс перебір parent заради min-cross) — ХИБНИЙ шлях: дає cross=0, але turns↑ (A* усюди).
Правильно — відтворити МЕТОД мокапа: (1) layout: head мульті-деп = перший root у порядку оголошення + нести деп
вертикально під джерелом; (2) routing: ДЕТЕРМІНОВАНІ елбоу на спільній шині для ієрархії (ceo→діти + внутрішньодеп),
РЕЗЕРВ-ПЕРШИМИ, A* лише для справжніх cross/secondary. Разом → 0 перетинів І рівні лінії, як у мокапі.
