## Ранжовані слайси (найбільше прибирає зигзаги першим)

1. **Слайс A — bus-консолідація cross-dept (§3.2 ряд. 54).** Коли керівник має кількох підлеглих в одному цільовому департаменті — ОДИН вхід у рамку (deptTop) + розгалуження шиною всередині, замість N окремих A*-входів. Найбільший різ по bends для fan-out (а мокап робить саме так). **Розмір: M.** Ризик: треба групувати specs за (from_id, target_dept) і будувати шину.

2. **Слайс B — routing_order за ціллю (§5.4 ряд. 112).** Додати до `routing_order` сортування за target.x (ліва ціль → ліва доріжка), щоб лейни вкладались без переплетення. **Розмір: S.** Низький ризик, швидка перемога на bends.

3. **Слайс C — пост-спрощення маршруту (§5.1.2).** Прохід, що прибирає зайві «сходинки» там, де прямший шлях лишається без порушень (штовхає до ≤2/≤4 поворотів). **Розмір: M.** Доповнює A/B.

4. **Слайс D — spacing рамок (§5.2, F2) = твоя «натягнути стилі».** Гарантувати 28px між РАМКАМИ (не картками): додати `content_padding` до block-gap у pack_tree_block. Прибирає «департаменти близько». **Розмір: S.** Найдешевша видима перемога, але bends не чіпає.

5. **Слайс E — порядок деп-блоків (§6.2).** Рішення: лишити attach_x (§6.3) чи сортувати за dept.order (§6.2). Звірити з порядком мокапа. **Розмір: S.** Може зачепити golden.

6. **Слайс F — layout-rebuild + динамічне розширення коридору (§5.2/§6.5).** Fallback-перебудова коли rip-up не чистить. **Розмір: L.** Низький пріоритет — детектор уже 0/0/0/0/0.
