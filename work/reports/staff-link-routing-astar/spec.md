# spec.md — React-хром near-view для ШПС alpha

**Слайс:** staff-alpha near-view chrome (рамки департаментів + org-рамки) 1:1 з мокапом v3.
**Статус:** SPEC. Попереднє: лінії+картки зроблено (коміт 617d873). Плани dg40 + критик — є.

## Problem
Near-view alpha малює картки (React, 1:1) і лінії (React-геометрія через Pixi), АЛЕ рамки
департаментів і org-рамки малює Pixi — наближено, не 1:1 із CSS-мокапом:
- шапка `.dn` у Pixi = 20px (labelFontSize+6), у мокапі = 34px (DPt=58);
- рамка береться з AABB членів, а не з `result.frames` (Rust) → інші пропорції + **вхідні
  крапки ліній пливуть** повз рамку (два джерела геометрії рамки, drift ADR-0002);
- org-рамок (керуюча/поточна) немає взагалі.
Pixi принципово не відтворює CSS точно (погоджено з власником) → хром має бути React/CSS.

## User scenarios
1. Користувач відкриває staff-alpha, зумить до mid/near → бачить рамки департаментів із
   залитою шапкою `.dn` (34px, назва + «N поз.»), картки всередині, лінії докуються на верх
   рамки з вхідними крапками, що сидять ТОЧНО на краю рамки.
2. Бачить org-рамки: керуючу (смугаста dashed, лейбл «Керівна організація», summary-картка) і
   поточну (solid, чіп «Поточна організація»).
3. При pan/zoom хром рухається синхронно з картками й лініями (один transform, без desync).
4. При far (<0.45) — Pixi як є (хром React не показується).

## Acceptance criteria
- AC1: на mid/near рамки департаментів рендеряться React/CSS із геометрії `result.frames`
  (Rust, єдине джерело); шапка `.dn` = 34px, fill #202023, назва біла 14/600, «N поз.» сірий mono.
- AC2: вхідні крапки ліній сидять на верхньому краю рамки департаменту (бо лінії й рамки тепер
  з одного джерела — `result.frames` / dept.y1).
- AC3: org-рамки рендеряться: поточна (solid #5a5a62, bg #0f0f11, чіп «Поточна організація»
  оранж border #e5491d); керуюча — смугаста dashed з лейблом (якщо в сцені є lead-org; у mock3
  нема lead-org → показуємо лише поточну + заглушку keruyucha як у мокапі опційно).
- AC4: Pixi staff chrome (zones/departments/edges) НЕ малюється на mid/near (LOD-гейт) →
  без подвійного паінту.
- AC5: pan/zoom — хром синхронний із картками (один camera-synced шар).
- AC6: far (<0.45) — Pixi staff як раніше; React-хром прихований.
- AC7: усі гейти зелені (SDK rstest, demo, typecheck); staff-shps/staff-mock3 не зламані.

## Out of scope
- Hover-підсвітка зв'язків (окремий слайс).
- Пошук v3 (.sbar + «Знайдено» + focus).
- Collapse/expand гілок (chevron поки статичний).
- Повний порт керуючої орги з реальними lead-org даними (mock3 їх не має).

## Open questions
- Q1: керуюча орга — показувати заглушку (як мокап «Головний офіс») чи лише коли є реальний
  lead-org? → рішення в plan (дефолт: показувати лише поточну; керуюча — коли є lead-org).
- Q2 (ВИРІШЕНО): z-order змушує лінії теж у React. React-шар (z5) над Pixi-canvas; рамки в
  backdrop були б НАД Pixi-лініями → перекрили б їх. Тож backdrop = рамки (низ) + SVG-лінії
  (середина, з тих самих `routes`), картки (верх, promote-слоти). Pixi staff повністю
  вимикається на mid/near (zones+departments+edges). Pixi-лінії лишаються для FAR. Мокап і так
  SVG — це 1:1, плюс дає non-scaling-stroke і підґрунтя для hover.
- Q3 (ВИРІШЕНО): геометрію chrome (frames/routes) demo рахує САМ через `computeStaffLiveGeometry`
  (SDK-експорт) один раз на монтування — той самий детермінований Rust-результат, що й Pixi-far
  (нуль drift), БЕЗ нового методу фасаду (facadeSurface-гейт: базис лише зменшується). Backdrop
  отримує {viewport, screen, lod}, конвертує world→screen.
