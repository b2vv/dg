**Нове (цей цикл):**
- **AC-0 метрик:** `true_turns(points)` (справжні зміни напрямку) + `turn_limit(кінці ребра)` класифікація за
  належністю кінців (внутр ≤2 / міждеп ≤4; `is_internal` def staff_router.rs:889), + `excess_turns = Σ max(0,
  true_turns − limit)` **лише по успішних ребрах** (не `failed`, не `marked` best-effort). У staff_routes.rs
  поруч зі stats (:667-672); додати в рядок `A*:`; rust-тест. **НЕ** чіпати route_stats. ⚠️ (N7) Для A*-ребер
  `simplify_points` уже дедупить колінеар (:1212), тож «виправити bends» — ймовірно no-op; AC-0 саме тому
  «ВИМІРЯТИ, не припускати роздутість». Колінеар-контрприклад — у Z-fallback (~staff_router.rs:1761, НЕ :642).
- **Слайс A (bus):** групувати cross-dept edge-specs за (from_id, target_dept) → один deptTop-вхід, далі
  РОЗГАЛУЖЕННЯ наявним tree-builder'ом §3.1 (N3 — НЕ будувати другий bus-рушій). Точка: staff_routes.rs:571.
  ⚠️ ВИКЛЮЧИТИ з групування `secondary`-ребра (bypass/SECONDARY_PORT, N4) — подвійне підпорядк. out-of-scope,
  але misroute наявних неприпустимий. ⚠️ Коли `target_dept=None` (ціль поза департаментом, §3.3) — ребро НЕ
  групується, йде як зараз (N5). N=1 підлеглий → вироджений вхід без шини (N6).
- **Слайс B (order-by-target):** ключ `routing_order` зараз `(secondary, start.1, start.0, idx)`
  (staff_router.rs:794-805) — `secondary` УЖЕ первинний (N1). Замінити `start.(1,0)` на цільовий `(target.x,
  target.y)`, зберігши `secondary` первинним і `idx`-tiebreak.
- **Слайс C (post-simplify):** прохід, що прибирає зайві сходинки з урахуванням заборонених зон І інших ліній
  (§5.3) — не лише карток. Розширити `simplify_points`. ⚠️ (N8) ГЕЙТ-пропуск: якщо після A+B усі ребра вже
  ≤2/≤4 (`excess_turns=0`), слайс C не потрібен — виміряти після B/A перед реалізацією C. `failed`/best-effort
  маршрути C НЕ чіпає (лишаються як є, виключені з excess_turns).
- **Слайс D (spacing):** у pack_tree_block (subtree_width :876 + place) збільшити горизонт. зазор між блоками
  так, щоб РАМКИ стояли ≥28px. ⚠️ (N2) рамка виступає `content_padding` з КОЖНОГО боку → потрібно
  `gap_між_блоками ≥ 28 + 2·content_padding` (не +однин padding).

**Чому не переюзали для нового:** bus-консолідації нема (per-edge A*); routing_order свідомо за джерелом (dg31);
simplify не враховує інші лінії; block-gap у pack_tree_block рахує картки, не рамки. Жодне наявне не покриває.

## Крайні випадки / кривий інпут (Q1, Q4 — plan-defense)

- **Кривий інпут (Q1):** валідація даних — ВИЩЕ за течією (спека §2: цикли/подвійний parent відхиляються до
  геометрії). Роутер/layout уже деградують штатно: self-loop скіпається (staff_routes.rs:572), dangling/деп-без-
  голови (:590). Циклічний parentId гарда в роутері НЕ має — покладаємось на upstream-валідацію (§2), це
  out-of-scope цього циклу. Слайс A групує specs ПІСЛЯ цих скіпів.
- **0 cross-dept ребер:** bus (A) — no-op (нема що групувати), решта без змін.
- **N=1 підлеглий у цільовому деп:** вироджена «шина» = один вхід без горизонталі (A2 допускає; AC-A1 «≥2» —
  саме про наявність консолідації, N=1 її не потребує). Назвати в тесті S1b.
- **target_dept=None (ціль поза департаментом, §3.3):** ребро не групується в bus, йде як зараз (N5).
- **Порожній department_frames:** pack_tree_block/роутер деградують (find_map по порожньому :595 → card-to-card);
  слайс D no-op. Покрито (критика: :746).
- **Відмова A* (ITER_CAP=250k або off-grid, Q2):** best-effort Z-лінія `failed:true` (~staff_router.rs:1761),
  НІКОЛИ не паніка. Такі ребра ВИКЛЮЧЕНІ з `excess_turns` (лише успішні рахуються) і слайс C їх не чіпає —
  AC-C1 `excess_turns=0` стосується УСПІШНИХ маршрутів, best-effort лишається marked.

## Rollback

- Кожен слайс — окремий локальний коміт (гілка feat/t126…, не пушиться). Відкат = `git revert <slice-commit>`.
- Слайси незалежні на рівні ефекту: B (sort key), A (bus grouping), C (simplify pass), D (region gap) —
  відкат одного не ламає інші (крім: C-тести спрощення залежать від AC-0 метрика — AC-0 відкочувати останнім).
- Якщо слайс не дає падіння/ламає detector — revert, лишаємо решту; excess_turns-метрик лишається як вимір.
