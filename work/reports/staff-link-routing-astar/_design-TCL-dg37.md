# Дизайн T-CL — channel-lane-ordering (прибрати X#4-9, mock3)

ДАЛІ: локалізувати, де народжується Y горизонтального пробігу довгої міждеп-лінії (A* vs явний lane), прочитати build_corridor_grid + occupancy у staff_router.rs.

## 1. Де народжується Y горизонтального пробігу
A*-сітка (build_corridor_grid staff_router.rs:379) сіє рядки Y: на краях перешкод + СЕРЕДИНА кожного широкого проміжку + пара ±LANE(8px). Горизонталь довгої лінії лягає на той grid-рядок, який A* обере за мінімумом cost = length + TURN_PENALTY + lane-вага (occupancy: own-lane × 0.15, foreign × 6000/4000). **Явного lane-рівня НЕМА — Y це A*-вибір.** Occupancy робить дорогим ЗБІГ сегментів різних керівників (вони «розпадаються» на різні рядки), але два рядки НЕ гарантують відсутність H×V-перетину — саме тому B(occupancy-порядок) не допоміг.

## 2. Алгоритм crossing-min (один міжтірний канал)
Модель: кожна лінія у каналі = горизонтальний інтервал [x_in,x_out] на рівні каналу + вертикаль-поворот (вниз до цілі на x_out, або вгору від джерела на x_in).
Перетин(A,B): вертикаль-вниз A на xA_out ріже горизонталь B ⟺ xA_out ∈ (B.x_in,B.x_out) І lane(B) НИЖЧЕ за lane(A) (A спускається крізь рівень B).
Правило (vertical-constraint): якщо A повертає вниз на x, а горизонталь B проходить над x і йде далі — A має бути НИЖЧЕ B (ближче до нижнього тіру). Це частковий порядок (constraint-граф); топосорт дає стек доріжок. Для ацикл-«сходинки» mock3 реалізовно.
**Проста коректна реалізація для патерну:** лінії, що ділять канал, сортувати за x_out (точка повороту-вниз) ↑; призначати доріжки від НИЗУ каналу вгору (найраніший поворот = найнижча доріжка). Лінії, що «пролітають» далі вправо (ceo-віяло), опиняються вище за спуски ліворуч від них.
**Доказ на X#4:** cfo→ah x_out=5258; ceo→hrd пролітає до 6242 (над 5258). sort: 5258<6242 → cfo→ah нижче, ceo→hrd вище → спуск cfo→ah стартує нижче ceo-горизонталі → НЕ торкає. Збігається з доведеним fork-фіксом (ceo вище). X#5-9 — той самий патерн (cfo→ah/cto→bi спуски в ana x5258/5586 проти ceo→hrd/lgl/sch вправо 6242/7062/7718): усі descents лівіше за continuations → усі 6 розв'язуються.

## 3. Інтеграція
Не cost-bias (не гарантує — доказ: B). Детермінований channel-lane pre-pass:
- Згрупувати маршрути, чиї горизонт-пробіги ділять один міжтірний band (y-смуга між тірами).
- Обчислити lane-порядок (sort за x_out, bottom-up), stable + id-tiebreak.
- Застосувати: (варіант A) обмежити A* рядком для channel-пробігу кожної лінії; (варіант B, простіший) пост-коригувати Y горизонт-пробігу + перезшити вертикалі, re-check перешкод. Лягає ПІСЛЯ per-edge A*, в межах/перед rip-up. Внутрішньодеп-елбоу (int-edges, staff_router.rs:903) і deptTop-входи ВИКЛЮЧИТИ — лише inter-tier highway-пробіги.

## 4. Пастки
- **Ширина каналу:** N доріжок = N×8px+кліренс; tierGap=120 → ~15 доріжок, для 6 влазить. Якщо не влазить → widen (§6.5/F).
- **Загальність:** мульти-канал + вертикалі в обидва боки = повне channel-routing (L). Цикл у constraint-графі → не розв'язно без реордеру. Таргетна одно-канальна «сходинка» (mock3) = M, але не універсальна.
- **rip-up/occupancy:** після lane-переприсвоєння перерахувати occupancy для каналу (або замінити для нього).
- **Детермінізм:** stable sort + id-tiebreak.
- **Не-mock3:** лише mock3 на A*+deptGrouping; пас МУСИТЬ no-op при ≤1 лінії в каналі.

## 5. Тест
Дискримінаційна фікстура: 2 лінії в одному каналі з інвертованим x_out (ліва спускається раніше), СТАРИЙ A* дає перетин, новий пас — ні. + вимір cross на mock3 X#4-9 → 0. HUD excess/turns не зростають.
