## Проблема

🔴 **ВИПРАВЛЕНО dg37 (T-A0 baseline, вимір Codex):** попереднє твердження «D у детекторі вже
0/0/0/0/0 як мокап» було ХИБНЕ — число cross=0 взяте зі скріна конфіга A (до dg35, без
deptGrouping). Реальний baseline конфіга D (виміряно route_stats напряму, і на HEAD, і після T-A0):
**cross=9**, over=0, card=0, near=0, dept=0, **true_turns=126, excess_turns=22**, marked=0, edges=50.
Тобто dg35 (увімкнення deptGrouping) РЕГРЕСУВАЛО cross 0→9 (форма мокапа ціною перетинів).

Таб `staff-mock3` (deptGrouping+tree-block, dg35) має **9 справжніх перетинів** (мокап — 0) + зайві
повороти (excess_turns=22; bends=126 — це РЕАЛЬНІ повороти, колінеар-фікс на цій сцені no-op).
Різниця з мокапом — НЕ лише естетика: є топологічні перетини. Машинерія роутера (occupancy, rip-up,
turn-penalty, deptTop) є, але недотягнута. Gap-аналіз локалізував корені (вони б'ють і по cross, і по
turns): bus-консолідація (A), порядок доріжок за ціллю (B), пост-спрощення (C), spacing (D):

- **A (§3.2):** кожне cross-dept ребро йде окремим A*-входом у рамку; мокап робить ОДИН вхід у
  департамент + шину (bus) до кількох підлеглих одного керівника. Найбільший внесок у bends.
- **B (§5.4):** `routing_order` сортує за ДЖЕРЕЛОМ (start.y/x), а спека вимагає за ЦІЛЛЮ («ліва
  ціль → ліва доріжка»). Лейни переплітаються.
- **C (§5.1.2):** turn-penalty штрафує повороти, але не гарантує ≤2 (внутр.) / ≤4 (міждеп.);
  зайві «сходинки» лишаються — нема пост-спрощення маршруту.
- **D (§5.2):** рамки департаментів стоять ближче за номінал 28px (horizontalGap=28 — це gap між
  КАРТКАМИ, а рамка виступає на `content_padding`), тож департаменти візуально тісні.

## Користувацькі сценарії

1. Власник відкриває `staff-mock3` і бачить лінії зв'язку **без зайвих зигзагів** — як у мокапі:
   один вхід у департамент, шина всередині, прямі вертикалі.
2. Керівник з підлеглими в одному цільовому департаменті — від нього **одна** лінія входить у
   рамку згори, далі розгалужується шиною (а не N паралельних заходів).
3. Кілька ліній в одному коридорі не перехрещуються при вході/виході: порядок доріжок = порядок
   цілей зліва направо.
4. Департаменти **візуально розділені** (рамки не злипаються), читаються як окремі блоки.

## Acceptance criteria

**Естетичний гейт (замкнено GATE 1, синтез 2 критиків — Opus + Codex):** гібрид. Петля слайсів =
візуальна звірка власником + топологічний detector. ПЛЮС вимірюване доповнення:
**`excess_turns = Σ max(0, справжні_повороти − ліміт)`** по **успішних** ребрах (не `failed`/best-effort
`marked`; §5.1.2 ліміт: внутр ≤2, міждеп ≤4; класифікація ЗА КІНЦЯМИ ребра через `is_internal`, не за
`ends_on_dept_top`). Рахується на **справжніх змінах напрямку** (dedupe колінеарних), ОДИН підрахунок для HUD
і тестів.

**Гейт per-slice:** cross/over/card/near/dept **не зростають** (ціль циклу — ГНАТИ cross 9→0, не
«лишатись на 0»: baseline cross=9) + сумарні справжні повороти **не зростають** + власний AC слайса.
Цільові показники фіналу: **cross=0** (як мокап) + **excess_turns=0**. A/B б'ють по cross; C по turns;
D по spacing. Фінал «достатньо чисто» = **візуальна звірка власником** — числа її не замінюють.

- **AC-0 (baseline):** спершу перевиміряти baseline СПРАВЖНІХ поворотів на mock3 (не припускати, що
  `bends=126` роздутий колінеарними — A* уже кличе `simplify_points` staff_router.rs:1212, тож для A*-ребер
  фікс bends імовірно no-op; колінеар-контрприклад — у Z-fallback ~staff_router.rs:1761, НЕ :642). Перевірка:
  вивести true-turns + excess_turns на поточному D. Doc-fix: виправити bends-підрахунок (points.len()−2 →
  справжні повороти), HUD+тест один підрахунок. Жоден наявний тест bends не асертить (safe).
- **AC-A1 (bus):** для керівника з ≥2 підлеглими в одному цільовому департаменті існує РІВНО один
  перетин верхньої межі рамки цього департаменту цим керівником (один deptTop-вхід), а не N.
  Перевірка: тест рахує входи рамки per (from_id, target_dept) == 1.
- **AC-A2:** внутрішньодепартаментне розгалуження від цього входу — шина (горизонтальний відрізок)
  + вертикалі до кожного підлеглого (§3.1 форма).
- **AC-B1 (order-by-target):** у спільному коридорі доріжки впорядковані за X цілі: ціль лівіше →
  доріжка лівіше. Перевірка: тест на сцені §10.1.4 (два керівники → один департамент C) — лінії
  не перетинаються і порядок доріжок монотонний за target.x.
- **AC-C1 (пост-спрощення):** жоден маршрут не містить «сходинки», яку можна прибрати прямішим
  орто-шляхом без порушення заборонених зон — враховуючи §5.3 (ІНШІ лінії, не лише картки).
  Внутр. ≤2 повороти, міждеп. ≤4 (§5.1.2). Перевірка: конкретні тести «зайва сходинка прибрана» +
  «необхідний обхід збережено» на визначених категоріях mock3; `excess_turns=0`; сум. повороти падають.
- **AC-D1 (spacing):** відстань між РАМКАМИ сусідніх департаментів одного рівня ≥ 28px (§5.2),
  а не між картками. Перевірка: тест на межах рамок у pack_tree_block. (Власну користь має БЕЗ
  зниження поворотів — від D падіння bends НЕ вимагається.)
- **AC-детермінізм:** однакові дані → однакова схема (golden-determinism лишається зеленим).
- **AC-регресія:** усі наявні гейти зелені (rust test, SDK, demo, typecheck, clippy, fmt);
  golden інших табів не змінюється (mock3 виключений з baseline).
