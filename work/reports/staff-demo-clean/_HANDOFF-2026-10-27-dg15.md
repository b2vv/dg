# 🐞 ДЕТАЛЬНИЙ РОЗБІР БАГА: керівна орг «закинута вліво» (міжярусна X-розбіжність)

> На прохання власника — зафіксовано для окремого розбору. Фікс застосовано (див. вище),
> але є відкриті питання й прогалина тест-покриття — НЕ вважати закритим без обговорення.

## Симптом
ШПС-сцена: картка керівної орг (Генеральний директор / «Головний офіс», ярус-1) рендерилась
біля ЛІВОГО краю свого ярусу, а не центровано над головою поточної орг (Директор, ярус-2).
Cross-tier лінк ішов «вниз-і-вбік» замість строго вертикального (мокап `.plink` — вертикаль по
центру). Візуально — велика порожнеча праворуч усередині зони «Головний офіс».
Скрін до фіксу: `screenshot-1793055971280-4.jpg` (власник обвів червоним порожнечу).

## Де
`packages/sdk/src/layout/staff/canvasLayout.ts`, `layoutStaffCanvas`.

## Корінь (root cause)
1. Ярус-1 будується `layoutStaffOrgBlock(leadership, …, managingId, …)` (~рядок 71). Повертає
   блок у ВЛАСНИХ локальних координатах, що стартують від `geom.margin` зліва (кожен org-блок
   кладеться від лівого краю).
2. До вузлів ярусу-1 застосовувався ЛИШЕ Y-зсув (`n.y + cursorY + zoneLabelBand`, ~рядки 75-79).
   **X лишався локальним (лівий margin).**
3. Ярус-2 будується теж від свого лівого margin, але він ШИРШИЙ (два відділи поряд + recenter
   голови над прольотом) → голова-Директор опиняється посередині широкого прольоту (центр-X ~770).
4. Голова ярусу-1 (центр-X ~150) і голова ярусу-2 (центр-X ~770) НЕ співвісні → ~600px «вліво».
5. Внутрішньоблоковий recenter (`orgBlockLayout.ts:87-102`) тут НІ до чого — він центрує корінь
   над дітьми В МЕЖАХ одного блоку. **Міжярусного X-вирівнювання не було взагалі.**

## Чому раніше не бачили (важливо для розбору)
На `mockup-staff-figma` керівна (holding) і поточна (region) орг-блоки мали СХОЖУ ширину
(обидва ~3-карткові ряди) → голови випадково майже співвісні, баг маскувався. ШПС — перша сцена,
де ярус-1 вузький (1 картка), а ярус-2 широкий (2 відділи) → розбіжність стала явною.
Перегук із Q2: асиметрія ширин ярусів ламає візуальну вісь.

## Фікс (застосовано — обговорити коректність)
`canvasLayout.ts`, після лейауту ярусу-2:
```
mgrHeadId  — захоплено при білді ярусу-1 (head.id керівної орг)
curHeadPos — positions: organizationId===currentOrgId && isHead===true
dx = (curHeadNode.cx) - (mgrHeadNode.cx)   // cx = x + width/2
if (dx > 0)  усі вузли tier===1  →  n.x += dx
```
- Зсув ЛИШЕ праворуч (dx>0): вузький ярус-1 над широким ярусом-2 — праворуч ніколи не виштовхне
  за лівий margin. dx≤0 (керівна вже правіше) лишаю без змін → без регресій на наявних сценах.
- Cross-tier ребро деривується з боксів downstream → перемальовується вертикально автоматично.
- Перевірка: typecheck ✓; `npx rstest run layout/staff` 122/122 ✓; браузер — лінк вертикальний
  (`screenshot-1793056561355-5.jpg`).

## ⚠️ ВІДКРИТІ ПИТАННЯ (для розбору — фікс НЕ вважати фінальним)
1. **Прогалина тест-покриття (найважливіше).** 122 наявні тести були зелені І ДО, І ПІСЛЯ фіксу —
   отже ЖОДЕН не перевіряє міжярусну вісь (інакше падали б до фіксу). Фікс **не підтверджений
   тестом**. Треба rstest на canvasLayout: вузький ярус-1 над широким ярусом-2 → центр-X голови
   ярусу-1 == центр-X голови ярусу-2 (±1). Пам'ять `assert-true-without-feature` / `measurement-boundary-claims`:
   «зелено і до, і після» = відсутність інформації, не доказ.
2. **Чи правильний шар?** Можливо центрування має бути СИСТЕМНИМ — усі яруси навколо спільної
   вертикальної осі (голова поточної орг), а не лише ярус-1↔ярус-2. Ярус-3 (дочірні орг-картки)
   кладеться від `cardX = margin` (~рядок 144) — для ШПС порожній, але для сцен із ярусом-3
   знову розійдеться.
3. **Кейс dx≤0.** Якщо керівна орг ширша за поточну, голова ярусу-1 правіше — зараз нічого не
   робимо, ярус-2 лишається ліворуч від керівної голови. Коректніше — зсувати вужчий/лівіший
   ярус навколо спільної осі. Потрібне узгоджене рішення (симетричне центрування).
4. **Пост-зсув vs offset до лейауту.** Зараз пост-зсув вузлів. Альтернатива — передати offsetX
   у `layoutStaffOrgBlock` для ярусу-1 ДО лейауту. Перевірити, чи пост-зсув не конфліктує з
   іншими пост-кроками (`pinExternalManagers` та ін.).
5. **Zone bounds ярусу-1 занадто широкі (окремий, але суміжний баг).** Навіть після центрування
   зона «Головний офіс» ширша за картку (тягнеться майже на всю ширину). Причина —
   `staffZoneBounds.worldBoundsForTier` рахує bounds з урахуванням `canvasWidth`/інших вузлів, а
   не компактно навколо членів ЦЬОГО ярусу. Мокап: керівна орг — компактний бокс навколо однієї
   xcard. Рефайн: для tier-1 зону рахувати тільки навколо вузлів ярусу (+padding), не на canvasWidth.
