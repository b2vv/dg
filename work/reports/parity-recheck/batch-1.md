## 🔴 Побічна знахідка поза каталогом: гейт `check:docs` сліпий до getter-ів

Шов, яким хост гасить застарілий герб, — це `get media(): DiagramMediaFacade`
(`OrgHierarchyDiagram.ts:491`). Він **публічний і недокументований**, і гейт, який існує рівно
щоб такого не було, його **не бачить** — двома незалежними дірами:

1. **Регекс не ловить аксесори.** `scripts/check-docs.mjs:126` вимагає `(` одразу після імені:
   `/^ {2}(?:async\s+)?([a-z][A-Za-z0-9_]*)\s*(?:<[^>]*>)?\(/`. Рядок `  get media(): …` дає
   кандидата `get`, далі очікується `(`, а стоїть ` media(` → збігу немає. Прогнав логіку гейта
   як є: `publicMethods.size = 65`, `publicMethods.has('media') = false`.
2. **«Задокументовано» = голий підрядок.** `:131` — `usage.includes(name)`. Навіть якби аксесор
   потрапив у множину, `usage.includes('media')` = `true` **через рядок про дані**:
   `docs/USAGE.md:80` — `` | `persons` | люди (`fullName`, `photoUrl` / `media`) | ``. Це єдиний
   збіг у всьому файлі.

Тобто борг «8 недокументованих» — **не повний перелік**, а перелік того, що ловить регекс.
Сьогодні аксесор рівно один, тож ціна — один метод, не клас проблем; але заявлена межа
«publicMethods може лише зменшуватись» не виконується для аксесорів **за побудовою**.

**Заявка до Dg 1** (`scripts/**` — його смуга, не моя): `scripts/check-docs.mjs:124-131`.
Мінімальна правка — додати гілку на `get|set` в регекс і зробити перевірку документованості
точнішою за `includes` (напр., вимагати `` `name` `` у бектиках). Обидві половини треба
міняти разом: лише перша дасть хибно-зелений через п.2.

### D6 · «Search + focus» — заявлено `✅ 100` → **ЗАВИЩЕНО**

| | |
|---|---|
| Ліворуч | Пошук **у хості**, не в рушії: клієнтський фільтр по знімку в комбобоксі (`org-hierarchy-search.tsx:36-42`). Але доктрина вибору записана дослівно (`:20-23`): *«Picking an item centres the canvas on that node **(and clears any prior selection)** WITHOUT opening the details sidebar — the sidebar stays click-only.»* Тобто фокус **знімає** виділення і **не** веде в сайдбар |
| Праворуч | `focusNode` (`OrgHierarchyDiagram.ts:1545-1555`) робить **протилежне**: `this.applySelection(ref)` → `selectionStore.replace(ref)` (`:553-555`) — тобто **ставить** виділення на знайдений вузол, і лише потім пан |

**Наслідок, який видно без запуску:** хост тримає мультивибір для гуртових дій. У GoJS пошук
його **очищає** — після пошуку виділеного немає. У `dg` пошук лишає **рівно один** виділений
вузол (знайдений), і наступна гуртова дія застосується не до того набору. Плюс `applySelection`
доходить до `onSelectionChange` (`:289`) — хост, що вішає сайдбар на виділення (а не на клік),
відкриє його на пошуку, чого чинна доктрина прямо забороняє.

**Чи є обхід:** так, але не тим методом, що названий для цього. `focusNode` — єдиний публічний
«центруй на вузлі», і він виділяє. `panToNode` **приватний** (`:983`); публічний `panTo`
(`:1658`) хоче світові координати. Дістати їх можна `listPromoteBoxes()` (`:1604`) — публічний
API **overlay-промоушену**, не навігації, який віддає всі коробки й серед них треба знайти свою.
Тобто поведінка хоста досяжна, але через API іншого призначення й лише для вже відмальованих
вузлів.

**Чого в каталозі немає взагалі:** «worker + revealPath» описує **більше**, ніж хост просить
(хост шукає сам, у React). Але саме те, що хост просить — **фокус без виділення** — не описано
й не існує.

Додаю до його спостереження одну деталь, яка робить його різкішим: **`readSelectionPointerMods`
в барелі НЕМАЄ** (`grep -c` → `0`), хоч вона поруч у тому самому файлі
(`interaction/selection.ts:78-87`). Тобто експортовано все, чим модифікатори **обробити**, і
нічого, чим їх **добути**. Та й не допомогло б: полотно — Pixi, вказівникові події живуть
усередині SDK, до DOM хоста не доходять. Вхід недосяжний **структурно**, а не через недогляд
у списку експортів.

**Тому D1 розпадається на дві задачі різної ціни, і заводити його одним пунктом — помилка:**

| | Що треба | Ламає публічний API? | Потребує відповіді людини? |
|---|---|---|---|
| **Інформація** | другий **необов'язковий** аргумент: `onNodeClick(node, mods?)` | ні — хост, що ігнорує, компілюється як був | ні |
| **Власність** | перемикач, щоб SDK **не** застосовував свою політику першим | так — нова поверхня | **так** |

Без другої половини перша дає **подвійну поведінку**: SDK уже вибрав своє, хост вибирає своє
поверх. Тобто «дешево» стосується лише інформаційної половини; `grep selectionMode|allowMultiSelect`
→ нуль ловить саме другу.
