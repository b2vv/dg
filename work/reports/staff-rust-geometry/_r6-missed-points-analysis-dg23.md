## A. Повна staff-модель (яруси) — `canvasLayout.ts`
- **Ярус 1** = керівна орг: ЛИШЕ керівний склад (голова + прямі admin-підлеглі), `staff-block` (:67-97).
- **Ярус 2** = поточна орг: ПОВНИЙ штат, `staff-block` (:107-131).
- **Ярус 3** = дочірні орг як КАРТКИ (`org-cards`), згорнуті; expand-in-place під лімітом
  `maxExpandedOrgCards` (деф.1) → повний staff-блок під карткою (:157-231).
- **Cross-tier ребра:** `mgrHead→curHead` (1→2, :245) і `curHead→кожна дочірня orgCard` (2→3, :249).

**Org-картка = згорнута ієрархія цілої суборг** (власник). Експанд показує повний staff-блок;
колапс — одну картку. Це НЕ «ще один вузол», а згорнута піддіаграма.

## B. ПРОПУЩЕНІ моменти (кожен — з доказом)

**M1. Лінії до org-карток НЕ покриті спекою ліній.** `Вимоги - Лінії зв'язку ШПС.md` моделює
маршрути ВСЕРЕДИНІ однієї орг (депи, cross-dept) + плінк керівна→поточна (§3.4). Ярус-3
`curHead→childOrgCard` (2→3) там НЕ описаний. У SDK це 'cross-tier' ребро у картку. Семантика
кінця й стилю org-картко-лінку — НЕ вирішена. Ми ж у R6-3a трактували org-card як звичайну ціль
lookup (HOLE-2) — а це org-рівневий зв'язок до згорнутої піддіаграми.

**M2. Стиль org-рівневого лінку (ВИПРАВЛЕНО після роутер-мокапу).** Роутер-мокап
`ШПС лінії зв'язку.html` = ОДНА орг (депи+ceo), БЕЗ `.plink`. cross-DEPT лінія там — ТВІК
(«Як внутрішні/Штрих/Інший колір»), **дефолт суцільна**. Тобто:
  - cross-DEPT (особа→особа через депи, в межах орг) = СУЦІЛЬНА за замовч. → поточний SDK admin/cross
    солід КОРЕКТНИЙ, це НЕ баг. (Моє раніше «solid=баг» було хибне для cross-dept.)
  - `.plink` (штрих+мітка) = ORG-рівневий зв'язок (керівна→поточна, card v3 §3.4) — ІНША лінія.
    SDK має `mgrHead→curHead` як cross-tier СОЛІД → ОСЬ справжнє розходження (має бути плінк-штрих).
  - cross-tier `curHead→childOrgCard` (2→3) — теж org-рівневий, у жодному мокапі НЕ показаний.
Вхід-у-департамент (кружечок `.ent`) = deptTop-порт для head-цілей (легенда мокапу) — підтверджує
правило кінця з shps-links.js.

**M3. Expand/collapse змінює позиції й набір ребер — поза моделлю «R6 бере позиціоновані вузли».**
При expand орг додаються tier-3 вузли + їхні внутрішні edges (:193-201), а `curHead→orgCard`
ЛИШАЄТЬСЯ на картку (:249) — явного ребра картка→голова-розгорнутого-блоку НЕМА (блок висить під
карткою за позицією, не маршрутом). Колапс/експанд — повний re-`layoutStaffCanvas` (async,
generation-token R2). Routing має це переживати; ми не аналізували кейс розгорнутої орг.

**M4. cross-tier drop ПЕРЕТИНАЄ dept-рамки ярусу-2.** `curHead→orgCard` падає з верху ярусу-2 вниз
повз депи ярусу-2 до ярусу-3. Це може різати dept-рамки й картки — foreign-frame/clearance для
cross-tier ми не продумали (детектор R6-3a рахує лише те, що є; cross-tier геометрія «наївна»).

**M5. ШПС-специфічність.** Уся ярус/org-card/cross-tier/dept схема — лише staff-сцени
(`layout/staff/`). Rust-роутер має бути scene-scoped, не загальний. Не генералізувати.

**M6. matrix/dotted = штрихові = друге (функціональне) підпорядкування** (`StaffEdgesView.ts:24-25`),
яке спека §11.1 «відкладає». Прототип lines його вже має (p2). Узгоджено з рішенням власника
(лишаємо), але правило спеки «top=1 лінія» — лише admin; matrix/dotted мають власний стиль/маршрут.

## C. Що це означає для R6 (scope під питанням)
Спека ліній (dept cross-dept) ≠ повна staff-схема (яруси + org-картки + колапс). R6-1..R6-4
нарізані по спеці ліній, тож **org-картко-лінки й колапс/експанд не мають свого зрізу**. Треба
рішення власника ПЕРЕД подальшим кодом:
1. **Стиль/кінець org-лінку** (`curHead→orgCard` і `mgrHead→curHead`): штрих `.plink`+мітка (ціль
   мокапу §3.4) чи суцільний cross-tier (поточний SDK)? Кінець у картку-top чи у «рамку» орг?
2. **Колапс/експанд**: ребро до розгорнутої орг — у картку чи в голову розгорнутого блоку? Чи треба
   явний картка→head лінк? (зараз нема).
3. **cross-tier vs dept-рамки** (M4): cross-tier теж має обходити чужі рамки/картки, чи це окремий
   простіший клас (вертикальний коридор між ярусами)?
4. **Re-слайсинг R6:** додати зріз «org-картко-лінки + колапс» (ярусний рівень) поряд із
   dept-зрізами (R6-3b/4)? Чи org-лінки — окрема задача поза T126-R6?
