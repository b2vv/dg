## Правила (спека §3–§10) — ключове
- **Типи:** внутрішній (один деп) / міждеп (різні депи) / зовнішній (посада поза депом). Джерело — `parentId`.
- **Порти (§4):** `bottom`(вихід), `top`(вхід, рівно одна лінія), `deptTop`(вхід міждеп-лінії в рамку), `deptBottom`(вихід). Бічних нема.
- **Док у рамку депу `deptTop` ⟺ підлеглий = голова свого депу** (§3.2); інакше — у картку `top`. = поле `endsOnDeptTop`.
- **Міждеп (§3.2):** вихід з A знизу → коридори полотна → вхід у B зверху ОДИН раз → шина всередині B. Крізь рамку 3-го депу — ЗАБОРОНЕНО.
- **Маршрутизація (§5):** лише орто; min поворотів (внутр ≤2, міждеп ≤4); заборонені зони = картка+8px, заголовок депу+4px, чужі рамки; коридори; доріжки крок 8px; БЕЗ перетинів (інакше перебудова layout §6); детермінізм.
- **Layout (§6):** мусить ГАРАНТУВАТИ маршрутовність (підлеглий нижче керівника; сусіди за order; перебудова щоб прибрати перетини). Routing і layout ЗВ'ЯЗАНІ.
- **Критерії приймання (§10):** жодна лінія не перетинає іншу; не ближче 8px до картки; не під карткою/заголовком. + детермінізм. + перебудова на collapse/resize/dates/avatar/data (§8.3). Перф ≤50ms для ≤500 посад, rAF-throttle (§8.4).

## Висновок
«Правила правильного розрахунку link» = спека §3–§10 (існує). Rust їх НЕ задовольняє: однозначний баг (card_pad) + модель detour, яку треба довести до §10-критеріїв і звірити ВІЗУАЛЬНО з мокапом (не з TS — TS сам мав баги центрування, ADR-0002; §5 — SDK без споживача, еталон = мокап/GoJS хоста).
Це окремий суттєвий зріз (A* орто-роутер із §10-гарантіями), не «латка». Кандидат на spec-flow/власну задачу.
