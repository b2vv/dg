# R6-5 critic (Dg24)

ДАЛІ: читаю staff_routes.rs (увесь), staff_geom.rs, HANDOFF Dg23, plan.md §8 H6, tasks.md R6.

ФАКТ (прочитано): staff_routes.rs 1-792, staff_geom.rs 1-245, HANDOFF Dg23, plan.md:120 (H6), tasks.md:16 (R6).

ФАКТ Q1 (вакуумність): `staff_routes` (staff_routes.rs:234-312) — чиста функція. Нема HashMap/HashSet,
нема rand, нема clock, нема pointer-order. Усі ітерації — по слайсах у вхідному порядку
(edges:253, persons/org_cards find:101/107). `lanes` збирається у Vec (211-215) і СОРТУЄТЬСЯ (216-221),
тож навіть порядок перешкод нормалізується. Отже два прогони на ІДЕНТИЧНОМУ вході дають однакові
біти ТРИВІАЛЬНО (ті самі float-операції в тому самому порядку → ідентичні біти). Джерела наявного
недетермінізму НЕМАЄ. Висновок: 2-прогонний тест = регрес-guard проти МАЙБУТНЬОГО недетермінізму
(хтось замінить Vec+лінійний find на HashMap-ітерацію / rayon / BTreeMap-порядок), НЕ доказ фічі.

ФАКТ Q2 (найсильніша форма): порівнювати ВЕСЬ StaffRouteSet: lod + segments[] у тому ж порядку,
кожен — from_id/to_id/kind/points(усі, біт-у-біт)/marked. Типи (types.rs:6+) деривлять
Debug/Clone/Serialize/Deserialize, але НЕ PartialEq → для «байт-у-байт» найчистіше:
`serde_json::to_string(&a) == serde_json::to_string(&b)` (не чіпає прод-типи, порівнює весь набір
точно). ВАЖЛИВО: це exact-eq, не EPS 1e-6 як `points_eq` — для одного й того ж входу float
детермінований, тож exact коректний і сильніший (точно те, що вимагає рядок H6 «байт-у-байт»).
Фікстура: ≥3 перешкоди на ребро (щоб lanes мав кілька записів → спрацьовують sort(216)+dedup(217)+
tie-break(218-221)), ≥3 ребра у НЕвідсортованому вхідному порядку, суміш резолвних і залишкових,
≥1 marked=Some(true). Кілька рамок + кілька карток разом.

ФАКТ Q3 (float tie-break panic): `partial_cmp(...).unwrap()` (216, 220) панікує лише на NaN.
lanes = ry±pad, rh (211-215); corr0 = (from_bottom+to_top)/2 (207); da=(a-corr0).abs() (219) —
усі фінітні на фінітному вході. NaN виникає ЛИШЕ з не-фінітних координат (inf/NaN на вході) = F6
(кривий інпут), НЕ H6. Для H6 `.unwrap()` безпечний. Non-blocking нотатка: гарду на не-фінітні
координати нема — але це скоуп F6, не цього зрізу.

ФАКТ Q4 (мутаційний сенс) — КЛЮЧОВЕ: оскільки функція детермінована BY CONSTRUCTION, 2-прогонний
deep-equal НЕ ловить ЖОДНОЇ наявної мутації staff_routes.rs. Прибери tie-break `.then(...)` (220),
зміни dedup-eps (217), поміняй corr0-формулу (207), переставь порядок перешкод (160-171) — функція
ЛИШАЄТЬСЯ детермінованою, два прогони ЛИШАЮТЬСЯ рівні. 2-run тест червоніє лише на внесенні
РЕАЛЬНОГО недетермінізму (HashMap-iter / rayon / час) — а такого мутанта в поточному коді нема.
=> H6 як написано в plan.md:120 («двічі → ідентичні між прогонами») мутаційно НЕ верифікується.
Щоб зріз мав тестовий сенс — потрібен GOLDEN-снапшот: на мульти-перешкодній фікстурі асертити весь
StaffRouteSet проти явного очікуваного літералу (точки/marked/порядок). ТОЙ снапшот убиває
tie-break/dedup/corr0/порядок-мутації. Це єдина форма, що дає зрізу R6-5 мутаційну силу.

ФАКТ Q5 (прихований недетермінізм порядку): практично НЕМАЄ, і причина структурна. lanes будуються
у порядку перешкод, але ОДРАЗУ сортуються (216) → вхідний порядок перешкод не впливає на фінальний
набір. dedup_by (217) по вже-відсортованому → детермінований представник. segments[] = вхідний
порядок edges (збережено, вже покрито `preserves_input_edge_order` staff_routes.rs:452). Тобто
мульти-рамка/мульти-картка НЕ виявить прихованого порядкового недетермінізму — sort+dedup його
нормалізують. Але та сама фікстура Є цінною як ширший golden-снапшот (Q4): tie-break при двох
рівновіддалених від corr0 lane (один над/один під) — `.then(a.partial_cmp(b))` (220) детерміновано
бере менший (верхній); це АРБІТРАРНІСТЬ, яку снапшот запинить, а 2-run — ні.

РІШЕННЯ/ВЕРДИКТ:
- Blocking: 0 паст (зріз технічно коректний, функція детермінована).
- Non-blocking але РІЗАЛЬНЕ: H6 як написано (2-прогони) = тривіально зелений, мутаційно порожній.
  Рекомендація власнику: додати golden-снапшот весь-StaffRouteSet на мульти-перешкодній фікстурі —
  без нього зрізу бракує тестового сенсу (зелений-з-першого-разу без інформації, пам'ять
  `assert-true-without-feature`).
- Non-blocking нотатка: `.unwrap()` на partial_cmp безпечний для H6, вразливий лише на не-фінітний
  інпут (F6).
- Форма deep-equal: serde_json::to_string обох прогонів, exact-eq (не EPS).
