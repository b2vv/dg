що набір перешкод поки НЕповний проти §5.1 (свідомо), інакше вимір «0 порушень» буде оптимістичним.

## 3. Коридори + доріжки (§5.2, §5.4) — нова концепція «доріжок»
- Спільним коридором ідуть кілька ліній → паралельні **доріжки крок 8px**, порядок без перехрещень
  на вході/виході; ширина коридору ≥ `2·відступ + (N-1)·8 + lw`; бракує → **розширити**.
- Поточні зрізи R6 цього ПРЯМО не називають; найближче — R6-4 «around-frame lane + K-loop». Доріжки —
  окрема механіка (розподіл спільного коридору), не лише around-frame. **Додати в scope R6-4** або
  окремий зріз.

## 8. ВИВІРЕНО в `shps-links.js` (A*-прототип, 3-й артефакт; звід колеги dg-dd + моя звірка з джерелом)
**Відповідь на питання власника «чому одні деп→деп, інші особа→особа»:** джерело лінії завжди `p`
(parentId). Різниться лише КІНЕЦЬ, за правилом «ціль — голова депу чи ні»:
- `tgt(c)` = **верх РАМКИ** `[cx, d.y1]` ⟺ `d.head===c` і `kind≠int`; інакше **верх КАРТКИ** `[cx, cc.y]`.
- вторинне підпорядкування `p2` (`sec`) → верх картки зі зсувом +28px.
- джерело ЗАВЖДИ = низ картки керівника `[mx, mc.y+mc.h]` (НЕ deptBottom!).
- `kind`: `int` (та сама деп) / `cross` (різні деп) / `ext` (керівник без депу, ceo).
- `head = roots[0]`, roots = члени, чий parent ПОЗА депом (`!p.p||!inD(p.p)`); деп може мати КІЛЬКА
  коренів — у рамку йде лише перший (head), решта коренів (вторинний вхід) → у КАРТКУ. Це і є кейс
  bi/ib (особа→особа): депи ana/sec мають по 2 корені, head→рамка, 2-й корінь→картка.
- entry-кружечок (порт deptTop) малюється лише для head-цілей, `kind≠int` (render:187).

**ВИПРАВЛЕННЯ мого попереднього пункту:** `deptBottom` зі спеки §4 прототип НЕ використовує як порт —
вихід завжди з низу картки керівника, перетин рамки-джерела дає A*-обхід (`deptOK` role 'A'), не окремий
порт. Тобто з «frame-портів» реальний лише **deptTop для head-цілей**. Це ЗВУЖУЄ раніше заявлену
scope-прогалину: R6-1 (низ→верх карток) уже коректний для джерела ЗАВЖДИ і для НЕ-head цілей; бракує
тільки **верх-рамки для head-цілей** (+ entry-маркер).

**Розходження прототип↔спека (інфо):** (a) §3.2 «вхід у B один раз + шина» — прототип веде кожну лінію
незалежно для не-head; (b) подвійне підпорядкування §11.1 «не підтримується» — прототип ВЖЕ має (`p2`);
(c) стиль cross §11.2 «відкрите» — прототип має твік «Як внутрішні/Штрих/Інший колір». Прототип
випереджає спеку. card v3 = «зараз» (CSS-дерево, не виражає особа→особа), lines = ціль §9 (SVG+A*).
