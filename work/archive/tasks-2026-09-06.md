# Архів задач — вказівники (свіп 2026-09-06)

Другий свіп після [`tasks-2026-09-02.md`](./tasks-2026-09-02.md). Правило те саме
([`README.md`](./README.md)): **вказівник, а не копія** — копія тексту задачі розійшлася б з кодом
і почала б брехати, мертвий вказівник видно одразу. Повний текст лишається в історії git:

```bash
git log --diff-filter=D -- work/tasks/<ім'я>.md     # знайти коміт видалення
git show <sha>^:work/tasks/<ім'я>.md                 # прочитати останню версію
```

**Критерій цього свіпу — не «закрито», а «закрито І на це ніхто не спирається».** Так його
переформулював попередній архів після помилки з `T79`: задачу заархівували, а `work/SPEC.md` і
`docs/REQUIREMENTS.md` цитували її як **єдине** пояснення геометрії G1/G2/M2, тож посилання вело з
живої специфікації в архівний рядок. `T79` повернули; правило лишилось.

**Цей свіп — той самий «окремий свідомий свіп», якого просив `T92`.** Він прямо записав, що не
переїжджає, бо попередній прохід лишив тринадцять мертвих лінків, і що переїзд має бути окремою
роботою, а не побічним ефектом чужої гілки. Мертвих лінків цього разу нуль: `npm run check:docs`
зелений, усі посилання нижче перенаправлені.

**Статус наведено дослівно з самої задачі**, а не переказано з індексу.

звіт фіксує, на що спирався тоді, і правити його заднім числом означало б підробити запис. Тут
довелось відступити рівно двічі — `work/reports/auto-software-fallback/spec.md` посилається на
`T92` і `T98` **markdown-лінками**, а `npm run check:docs` вимагає, щоб кожен відносний `.md`-лінк
резолвився. Обидва перенаправлені сюди; текст звіту не змінено, статус задач наведено вище
дослівно, тож запис не спотворений.

`tasks.md:183`, що ведуть на `work/tasks/T92-...`. Гейт їх не бачить, а звіт має право фіксувати,
де задача лежала на день його написання. Читати їх тепер — звідси.
