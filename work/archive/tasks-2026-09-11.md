# Архів задач — вказівники (свіп 2026-09-11)

Третій свіп після [`tasks-2026-09-02.md`](./tasks-2026-09-02.md) і
[`tasks-2026-09-06.md`](./tasks-2026-09-06.md). Правило те саме
([`README.md`](./README.md)): **вказівник, а не копія**. Повний текст лишається в історії git:

```bash
git log --diff-filter=D -- work/tasks/<ім'я>.md     # знайти коміт видалення
git show <sha>^:work/tasks/<ім'я>.md                 # прочитати останню версію
```

**Критерій — «закрито І на це ніхто не спирається»**, як його переформулював попередній свіп після
помилки з `T79`. Перевірено по кожній: посилання перенаправлені сюди, `npm run check:docs` зелений.

🔑 **Чому свіп став дешевшим, ніж був.** Попередній прохід лишив **тринадцять** мертвих лінків, і
саме через них у `check:docs` з'явилась перевірка, що кожен відносний `.md`-лінк резолвиться.
Тобто ризик, яким свіп відсували, тепер **машинно закритий**: промах червонітиме до пушу, а не
через тиждень. Це той рідкісний випадок, коли стару причину «не робити» знімає не аргумент, а гейт.

**Що лишилось у `work/tasks/` попри закритість:** `T79` (жива `SPEC.md`/`REQUIREMENTS.md`
цитують її як єдине пояснення геометрії G1/G2/M2 — це і є та помилка, з якої виросло правило),
`T71` і `T56` (роадмап і каталог паритету — живі довідники), `T116`, `T117`, `T120` (закриті
**частково**: у кожної лишилась половина, що чекає рішення).
