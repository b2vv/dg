## 3. T111 — що знати, щоб не починати спочатку

**Відтворення (детерміноване):**

```ts
await page.getByRole('button', { name: 'Staff · Magnetic', exact: true }).click();
await page.evaluate(() => window.__demoE2e.moveSeat('pos-sup', 2, 2)); // pos-p2 сидить там
// → getLayoutDiagnostics(): ["Anchor overlap: pos-p2 vs pos-sup"]
// → якорі p-u2 і p-sup збігаються до пікселя
```

**Причина:** `interaction/positionMove.ts:50-73` не перевіряє зайнятість клітини.
`layout/staff/orgBlockLayout.ts:222` це **виявляє** і лише повідомляє.

🔴 **Це недоробка, а не нова фіча.** `work/SPEC.md:202` (§7) розподілив обов'язки з самого початку:
layout **лише діагностує** («v1 не розсуваємо anchors auto»), а не створювати накладання мусив
**D&D** — «Host/D&D має виправити». Layout свою половину виконує; D&D свою — ні (drag прийшов у
`fa82b5c`, T04).

**Дефект видно вже у проєкції.** `ContourPainter.previewDrag:373` переставляє лише перетягувану
посаду й нічого не робить із мешканцем цільової клітини — тому кільце розповзається **ще під час
перетягу**, до коміту. Саме це на записі користувача.

**«Назад не повертається» — наслідок, не окремий баг.** Дані цілі (API повертає місце без помилки),
але дві картки в одній точці ⇒ палець бере лише верхню.

**Рішення продукту:** посунути сусіда за напрямком перетягу; нікуди — поміняти місцями; спитати
лише у двох випадках, де автомат не має відповіді: напрямок невизначений (діагональ) або в
цільовій клітині вже двоє (легасі-накладання). План — [`reports/seat-collision/plan.md`](./reports/seat-collision/plan.md),
ключове там §1: **одна чиста функція `resolveSeatDrop`, яку питають і проєкція, і коміт**.
